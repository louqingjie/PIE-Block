# 疑似 PIE-Block 缺陷：证据模板

提交前先完成 `SKILL.md` 的三方对照；确认是生成器缺陷候选再上报。目标是一次性给出
可复现、可定位的信息，而不是让作者来回问。

## 提交到哪里

- **主渠道：飞书「机械培训群」**。学生把整理好的结论和证据发群里即可，不需要自己开
  GitHub Issue。
- 维护者需要留档时，会自行转成 GitHub Issue：<https://github.com/louqingjie/PIE-Block/issues>。
- `.pieproj` 只是普通参数，可直接发在群里，**不需要脱敏**；截图/日志里如果带本机路径、
  用户名或无关窗口，自己看一眼再发即可。
- **不要私聊发证据**（飞书组织限制也不支持私聊）：所有线索留在群里，别人也要能看到解决过程。
- 问题解决后，在同一个群话题里补一句结论（原因 / 修复版本 / 临时绕法），方便其他人搜索。

## 提交前自查

- [ ] 版本、系统、工程类型齐全；
- [ ] 有最小复现步骤，最好能用 `应用内模板` 或 `assets/examples/` 复现；
- [ ] 参数↔代码对照表给出了不一致的具体字段；
- [ ] 说明是否与版本/手改/导出文件不一致有关；
- [ ] 工程文件无需脱敏，可直接附上；截图/日志已确认不含无关个人信息。

## 不要做

- 不要附上你手改过的 `main.c` 作为"修复"；
- 不要建议作者"直接改生成器"绕过问题；
- 不要在群里发与问题无关的截图（例如桌面其他窗口）；`.pieproj` 工程文件可以直接发。
