# PIE-Block 本地启动说明

版本 1.5.0（build 7）　Windows / Linux 桌面应用　2026 年 10 月 22 日

本说明给出三条体验路径，以及从源码构建、启用编译与烧录的步骤；命令均已在 PIE-Block 1.5.0 仓库中核对。内容一致的 Markdown 版《本地启动说明.md》随源代码压缩包提供。

## 1. 作品与验证方式概览

PIE-Block 是首都师范大学 RoboMaster 机甲大师赛机器人图形化配置集成开发环境，面向 W.PIE 学生创新实验室 RoboMaster 校内赛。应用以分步向导完成步兵、工程、调试、音乐四类工程的配置与检查，生成 C 代码，并用随应用发布的离线 SDCC C251 工具链编译固件、烧录到 STC32G12K128 主控板。

（1）官网在线体验 https://pieblock.asia ：配置工程、查看生成的 C 代码；Web 版只读，不能编译与烧录，项目存于浏览器 localStorage。

（2）安装随包附带的 Windows 安装包：来源代码压缩包根目录的 `PIEBlock-1.5.0-windows-setup.exe`（取自官方 Release v1.5.0，约 22 MB，SHA-256 见同目录 `运行说明.txt`），双击安装后即可运行，安装包已内置离线 SDCC C251 工具链，无需 Flutter 环境，适合没有开发环境的评委。

（3）下载其他平台发布包 https://github.com/louqingjie/PIE-Block/releases ：提供 Windows 安装包、Windows 免安装 zip 与 Linux 免安装包。

（4）从源码运行：按第 3 节执行 `flutter pub get` 与 `flutter run -d windows`；未准备工具链时仍可配置、校验并生成 C 代码，完整编译与烧录见第 5 节。

## 3. 从源码启动

以下命令均在仓库根目录执行（仓库根目录即 Flutter 应用）。

**第一步：获取代码。**解压源代码压缩包或克隆仓库；编译固件与烧录还需 SDCC 子模块（未拉取也能启动界面并生成 C 代码）：

```powershell
git clone https://github.com/louqingjie/PIE-Block.git
git submodule update --init sdcc-c251
```

**第二步：安装依赖。**在仓库根目录安装 Dart 依赖：

```powershell
flutter pub get
```

**第三步：运行应用。**Windows 与 Linux 的开发运行命令分别为：

```powershell
flutter run -d windows
flutter run -d linux
```

首次运行需要构建 debug 产物，耗时数分钟属正常现象；启动后即可新建工程、完成配置向导、查看生成的 C 代码。

**低完整性目录的替代启动方式。**若仓库目录被安全软件或沙箱标记为低完整性（Low Integrity），`flutter run` 可能报 DevFS 创建失败或保存文件“拒绝访问”。此时改用仓库自带脚本，它先把 `build\windows\x64` 标记为 Medium 完整性级别，再执行 `flutter run`（参数原样传入）：

```powershell
tools\run_windows.cmd
tools\run_windows.cmd --release
powershell -ExecutionPolicy Bypass -File tools\run_windows.ps1
```

直接调用 .ps1 可能被拒绝加载（未签名），优先使用 .cmd；脚本默认补 `-d windows`。

## 4. 发布构建与产物

### 4.1 Windows

执行 `flutter build windows --release`，产物位于 `build\windows\x64\runner\Release\`，必须保留整个目录：`PIE-Block.exe`、`pieblock_hid.dll`、`flutter_windows.dll`、`data\flutter_assets`、`data\pieblock_runtime` 均为运行所必需。

Windows 安装包（可选，官方发布包由同一流程产出）：

```powershell
.\tools\package_flutter_windows.ps1
.\tools\package_flutter_windows.ps1 -SkipBuild
```

输出 `output\PIEBlock-1.5.0-windows-setup.exe`，需安装 Inno Setup 6（自动探测 ISCC.exe，或用 -Iscc 指定）；该脚本会先检查内置工具链，未准备时提示先运行 prepare 脚本。

### 4.2 Linux

Linux 发布构建与打包依次执行：

```bash
tools/prepare_sdcc_toolchain.sh
flutter build linux --release
tools/package_flutter_linux.sh
```

自包含产物位于 `build/linux/x64/release/bundle/`，发布时保留整个目录；打包脚本输出 `build/dist/PIEBlock-1.5.0-linux-x64.tar.gz`，可加 `--skip-build` 复用。只构建界面时可跳过工具链准备：CMake 仅在 `vendor/sdcc-toolchain` 存在时才装入 `data/pieblock_runtime`。

## 5. 启用完整编译与烧录（内置 SDCC C251）

发布版随应用携带离线 SDCC C251 工具链，无需另装 Keil 或 SDCC。工具链来自 sdcc-c251 子模块（GPL，https://github.com/louqingjie/sdcc-c251），构建时装入发布包；从源码构建需先编译并暂存一次。

**准备内置工具链（Windows）。**（1）拉取子模块：`git submodule update --init sdcc-c251`。（2）准备 MSYS2 构建依赖：脚本默认使用 `C:\msys64`（可用 `-MsysRoot` 指定），需要 MSYS2 UCRT64 环境中的 bison、flex、make、gcc 工具链与 zlib.h、boost/graph/adjacency_list.hpp 头文件；缺少时脚本会打印对应命令，例如：

```bash
pacman -S --needed bison flex make
pacman -S --needed mingw-w64-ucrt-x86_64-toolchain
pacman -S --needed mingw-w64-ucrt-x86_64-zlib
pacman -S --needed mingw-w64-ucrt-x86_64-boost
```

（3）编译并暂存工具链：

```powershell
.\tools\prepare_sdcc_toolchain.ps1
```

首次约需 20–35 分钟；`-Force` 强制重编，`-PackageOnly` 复用 `tmp\pie-block-sdcc-windows-install` 中已编译的安装目录，只重新暂存并生成 `vendor\sdcc-toolchain\bundle_manifest.json`。

**运行时部署。**CMake 构建时把 `vendor\sdcc-toolchain` 装入发布包的 `data\pieblock_runtime`；应用首次编译时再部署到 `%APPDATA%\com.wpie\PIE-Block\runtime`（约 24 MB），之后复用；固件缓存位于 `%APPDATA%\com.wpie\PIE-Block\builds`，来源或版本变化后自动失效。

**能力边界与本地 Keil。**无工具链时配置、检查、C 代码预览与导出均可用，“编译”“烧录”会提示缺少内置 SDCC 工具链。桌面版可在“烧录”页选用本地 Keil C251：目录需含 `UV4\uVision.com`（或 UV4.exe）与 `C251\BIN\C251.EXE`；出现许可证类错误需配置有效的 C251 许可证。

**Linux 端。**执行 `tools/prepare_sdcc_toolchain.sh`（支持 `--force`、`--package-only`），脚本走通 sdcpp、cc1、sdas251、sdld 全链路冒烟编译并生成 linux-x64 的 bundle_manifest.json，之后 `flutter build linux --release` 即装入工具链。

## 7. 硬件烧录简述

烧录只支持 STC32G12K128 主控板的 ROM USB-HID ISP：VID 34BF、PID 1001，Windows 免驱；不支持串口、蓝牙或外部 HEX。机械扩展板已固化程序，绝不可烧录。

连接 USB 前关闭四个开关：主控板 SERVO、主控板 POWER、扩展板 POWER、扩展板 BOOSTER。主控板只能断电后重新上电进入 ROM ISP；流程为 info → unlock → erase → 128 字节分块写入 → reset，硬超时 90 秒；成功后自动复位，再烧需重新上电。

操作入口在“烧录”页（仅编译、编译并烧录、烧录当前固件、导出 HEX、取消任务）。接线、开关位置与故障排查见 `docs/guides/Flutter编译与烧录指南.md`。

Linux 首次烧录前需安装 udev 规则：在应用“烧录”页点击“安装 udev 规则”（通过 pkexec 授权），或执行：

```bash
sudo tools/install_udev_rules.sh
```

安装后重新插拔主控板再检测设备。

## 8. 常见问题

**表 2　常见问题与处理方式**

| 现象 | 处理方式 |
| --- | --- |
| 中文用户名或中文临时目录导致首次编译失败 | 旧版按 UTF-8 严格读取 MAP 文件，中文路径会报“Failed to decode data using encoding 'utf-8'”；1.5.0 已改为宽松解码并补充回归测试。 |
| 首次编译提示“内置 SDCC 工具链部署失败……拒绝访问” | 多为杀毒软件或索引器占用刚复制的文件；1.5.0 已加入唯一暂存目录与重试（约 5 秒）。仍失败时可将 `%APPDATA%\com.wpie\PIE-Block\runtime` 加入白名单，或删除其中 sdcc 目录后重试。 |
| 首次编译比之后慢 | 首次需部署约 24 MB 的内置工具链，之后复用；“生成代码”页切到“汇编”会用内置 SDCC 完整构建一次，属正常耗时。 |
| 网页版能否编译或烧录 | 不能。Web 版只读，可配置并查看生成的 C 代码；编译、烧录与汇编列表仅在桌面版提供。 |
| Android 版能力 | 可配置、编辑与预览，但 Release 包未启用本地编译流水线，不能编译固件；烧录受 ISP 时序限制暂不可用，可“导出 HEX”后在桌面版烧录。 |
| 构建或打包提示缺少内置 SDCC 工具链 | 执行 `git submodule update --init sdcc-c251` 后运行 `.\tools\prepare_sdcc_toolchain.ps1`；只构建界面可直接 `flutter build windows --release`。 |
| 官网、文档与下载入口 | 官网 https://pieblock.asia ；仓库与 Releases：https://github.com/louqingjie/PIE-Block ；细节见 README.md 与 `docs/guides/Flutter编译与烧录指南.md`。 |
