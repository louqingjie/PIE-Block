# PIE-Block 1.4.0

调试测试序列改为**循环执行**并大幅瘦身提示音（删掉《卡农》完成音与结束回落，10 项一轮少 9.5 秒）；调试的摩擦轮测试项改为**直接填目标占空比**（500–800）；生成代码页移除手写汇编输出目标，改为点「汇编」**按需完整构建**并显示链接后的列表 `main.rst`；导出对话框新增「浏览」按钮，Android 上的导出改走系统文档选择器（原先必然失败）；仓库侧新增 P33 无源蜂鸣器 LPC 语音合成示例固件。

## 下载

| 文件 | 说明 |
| --- | --- |
| `PIEBlock-1.4.0-windows-setup.exe` | Windows 安装包，双击按向导安装 |
| `PIEBlock-1.4.0-windows-x64-release.zip` | Windows 免安装版，解压后运行 `PIE-Block.exe` |
| `PIEBlock-1.4.0-linux-x64.tar.gz` | Linux 免安装版，解压后运行 `pieblock_app` |

Windows 与 Linux 都内置离线 SDCC C251 工具链与 STC32G 固件模板，**无需另外安装编译器**即可编译并烧录步兵、工程、调试与音乐四类工程。Linux 首次烧录前仍需授权 hidraw 设备，可在应用内「烧录」页一键安装（行为与 1.3.0 相同）。

Release 同时附带稳定命名副本 `PIEBlock-windows-setup.exe` 与 `PIEBlock-linux-x64.tar.gz`，供官网直链使用（`/releases/latest/download/...`，不随版本号变化）。

**本次 Release 不附带 Android 安装包**：Android 流水线在打 `v*` 标签时会强制校验发布签名 Secrets，仓库没有配置，CI 会直接拦截标签构建（这条门禁 1.3.0 就已存在，所以 1.3.0 也没有附 Android 包）；Android 的 Release 构建另外还没有启用本地编译流水线，详见「已知限制」。

## 主要变化

**调试：测试序列改为循环执行，提示音只剩步序**

- 生成的固件把整段测试序列放进 `while (1)`：跑完最后一项后把八路输出全部归零、把 PWM 组频率复位到 main 起始的 50Hz，再回到第 1 项；循环边界与项间间隔一样留 1000ms 静默，所以「听到 1 声」就是新一轮开始。页面副标题与复核页摘要同步改为循环语义（「跑完最后一项自动回到第 1 项」）。
- **删除「全部完成」的《卡农》旋律**（多声部归并为单音线、854 音、约 5 分钟、每 2 秒循环）：序列不再有终态，也就不需要"全部完成"这一档；曲谱数据、`AllDoneCue()` 与试听面板的「全部完成」按钮一并删除。
- **删除结束区的下行回落**：回落按定义是上行音型的倒序去尾，不携带上行没说过的信息。实测 10 项一轮里上行合计 9400ms，回落 6520ms 外加专为它留的 3000ms 分区停顿——**每轮少 9520ms**，而序列现在是无限循环，这 9.5 秒每轮都要付。项 1 与第 6 项跳过落音后为空、只能退回音型首音的同音高退化歧义也随之消失。单步提示现在只有一段：上行 N 音（≤1.7s）+ 动作前 300ms 停顿；「这一项做完了」改由动作停止、1s 静默与下一项上行共同表达。
- **删除提示音风格开关（标准 / 紧凑）与项目字段 `cue_style`**：时值固定为唯一一套常量（单音 220ms、音间 140ms、分区停顿 300ms）。删除前后生成的固件与试听 WAV **逐字节一致**（标准档本来就是这套值），所以不改变行为，只是不再提供紧凑档；旧项目里的 `cue_style` 被忽略。
- **修试听合成的「破音」**：旧的 22.05kHz 朴素方波在高音区（第 9/10 项的 4186Hz / 5274Hz）会凭空产生 32%~35% 幅度的非谐波假分量，而真机 PWM 是按频率连续翻转、没有这个问题。合成改为 `lib/src/debug_cue_wav.dart` 的 **48kHz 带限方波**（奇次谐波求和，只取低于 Nyquist 的项），App 内试听与离线导出共用同一个函数；加窗 FFT 复核带内最大非谐波分量降到 **0.01%~0.04%**，峰值无削顶，三次谐波仍保留（听感仍是方波）。
- **调试页瘦身**：顶部三条说明 banner（摩擦轮激活与斜坡、提示音口诀、满油上限）全部删除，页面直接以试听面板开头；试听面板删掉「步序提示」标题行、说明段与风格开关，只剩标题「提示音试听」与一排逐项按钮，口诀由按钮标签表达（「第 N 项 / 低·高音区 · 上行 N 声」）。
- 实测体积（SDCC 离线编译）：固件源文件 9242 B / `.ihx` 8381 B；移除结束音之前为 10953 B / 9025 B，移除《卡农》之前为 28314 B / 43355 B。
- 方案、取舍与验证细节见 [调试模式提示音方案](docs/design/调试模式提示音方案.md)。

**调试：摩擦轮测试项改为直接填目标占空比（500–800）**

- 调试项目的摩擦轮测试项不再走「0–100 油门% × 该引脚满油上限」换算：`value` 现在**就是目标占空比本身**（500–800），写的就是这张卡实测想跑的占空比，不必先反推油门比例。调试项目也不再保存 `friction_p64_max_duty` / `friction_p66_max_duty`（步兵工程仍在用这两个上限做左右转速补偿，不受影响）。
- 校验：超出 500–800 报**错误**；**低于 650 只给提醒**（文案「可能带不动摩擦轮，观察不到有效结论」），避免 600~650 这一段被误当成能跑。提醒阈值在本次迭代中从 600 提到 650。
- 保留的行为：先用 `500` 启动占空比保持 1 秒完成电调激活，再逐周期（±1 duty）平滑渐变到目标，到位后停留 1.5 秒再归零；测试期间不发方向帧。
- 影响面：1.3.0 保存的调试项目里摩擦轮项存的是 0–100 的油门百分比，打开后会因低于 500 报校验错误，需要按目标占空比重填（见「升级提示」）。

**生成代码页：移除手写汇编输出目标，汇编栏改为按需构建并显示链接后的 `main.rst`**

- **移除手写汇编输出目标**：`pieblock_core` 不再有汇编生成器，音乐项目不再能「直接生成等价汇编并导出 `main.asm`」；随之失效的 `docs/guides/汇编生成器.md` 一并删除。
- 进入「生成代码」页**只显示 C，不编译**。代码区右上角保留「C 代码 / 汇编」切换器，点「汇编」才用内置 SDCC 发起**一次完整构建**（编译全部源文件 + 链接），期间用全屏遮罩显示阶段文案；同一份配置再次切到「汇编」直接复用上次结果，「重新编译」可手动重跑，配置改动导致 `main.c` 文本变化时会重新构建。
- 汇编栏展示的是**链接后**的列表文件 `main.rst`（`<目标名>_<序号>.rst`）：每行前 40 列是地址、机器码、指令周期与汇编行号，正文是 as251 汇编，C 源码以 `; main.c:66: …` 锚点插在对应位置。前 40 列整体弱化显示，助记符、寄存器、伪指令与注释按 as251 语法着色。因为要算出真实地址与机器码，这一步必须完整构建（不再是从前的 `-S` 预览），但产物与烧录一致，且构建结果**同时进入固件缓存**，随后到「烧录」页通常不必重新编译。
- 构建始终使用**内置 SDCC C251**，与烧录页选择的编译器无关；Keil C251 的产物可能略有差异。
- 只有一个代码区，C 与列表互斥显示，行号就是各自文本的行号，两边都可搜索与复制，导出分别是可编译的 `main.c` 与列表原文 `main.rst`。窄屏下整栏一起切换（文本、行号与语言着色同时换掉），测试覆盖了切到汇编再切回 C 的用例，不会再出现「标题是汇编、内容还是 C」的串台。
- **Web 与 Android 不提供汇编列表，只有 C**：点「汇编」会就地说明原因，页面降级为只有 C 栏。
- 实测：`PIEBLOCK_RUN_SDCC_GOLDEN=1` 跑 6 个工程，HEX 哈希与冻结基线一致，每个工程都带回 17~28 万字节的列表。

**烧录页改名：「编译与烧录」→「烧录」**

- 四类工程的向导最后一步现在都叫「**烧录**」，与「生成代码」页分工：编译变成生成代码页里按需触发的一次构建，最后一步只负责编译器选择、编译产物、导出 HEX 与烧录。文档、README 与官网文案同步改名；Web 版该页副标题说明汇编与烧录请在桌面版完成。

**导出对话框新增「浏览」按钮，Android 导出改走系统文档选择器**

- 桌面：点「浏览」弹出系统保存对话框（按扩展名过滤、默认落在当前目录），把选中的完整路径回填进输入框；路径仍可手输，「导出」照旧落盘。
- Android：SAF 没有可输入的路径，输入框改为只读，「浏览」与「导出」都直接走系统文档选择器把内容写进去——原先用 `File(路径)` 写盘在 scoped storage 下必然失败，这条路径等于修好。
- 写盘改走 `AppDocumentIo.write`，与项目保存共用同一条平台实现。
- 「浏览」打不开文件管理器、或写盘失败时给 SnackBar 提示且不关闭对话框，不再把异常抛到对话框回调里。

**示例固件：P33 无源蜂鸣器 LPC 语音合成（`BUZZER_VOICE_SMOKE`）**

- 把 P33 无源蜂鸣器**当扬声器**用：PWM 载波固定 129.6 kHz（`FOSC/256`，正好给出 8 位占空比分辨率），每个采样周期写一次比较值，50% 占空比等于无声；载波远高于音频带，压电片自身的机械低通把占空比还原成音频包络，于是能播出 10 阶 LPC 格型合成的中文短句「这是P六零，电机调试」与「这是P六十，电机调试」。
- 约束候选集下的中文识别器对「六十」版给出约 **0.989** 的置信度命中（对照：干净 TTS 参考音做开放听写也只有 0.19 置信度且会写错字，所以结论以约束候选集为主）。音质是对讲机 / 贺卡级别，不能当正常喇叭用。
- **修「播放慢 3.6 倍」**：第一版在 8 kHz、每样本约 25 次 **32 位乘法运行库调用**（`ecall __mullong`，由实测反推约 466 周期/次）合计约 449 µs，而 8 kHz 的预算只有 125 µs，中断被持续追尾、实际采样率掉到约 2.2 kHz（实机表现：P35 亮 12 s 才换灯，正是 3.34 s 的 3.6 倍）。热路径改为不做 32 位乘法（8×8 硬件乘 `mul ab`、8 位系数无分支、插值只用一条 `mul ab`、激励增益每子步预算、热状态放近内存、格型乘法宏内联），采样率改为 7.2 kHz（预算 139 µs），估算 **129.7 µs / 138.9 µs = 93%**；`check_voice_model.py` 会扫 `voice_synth.asm`，热路径里出现 32 位乘除运行库调用直接判失败。
- **响度**：压电片只在谐振带（约 2–4 kHz）效率高，而语音能量集中在 500 Hz–1 kHz。软件侧把峰值提到 96%、载波降到 64.8 kHz、加压缩（γ=0.7 / 帧压缩 0.75），压电域 RMS 从 3312 提到 **5821（+4.9 dB）**，仍是 0% 削顶；再往下（0.6/0.65、0.5/0.55）每档只多约 0.5 dB 而失真明显上升。软件侧已到极限，剩下只能提高驱动电压（3.3→5 V +3.6 dB、→12 V +11 dB、桥接再 +6 dB，或换小喇叭 + 功放 +20~30 dB）。
- **实机频响实测**（用户录音扫频分析）：基频响应跨度约 48 dB，500 Hz 为 −48.5 dB、1.6 kHz 为 −26.5 dB、2.0 kHz 为 −10.2 dB、4.5 kHz 为 0.0 dB（真实谐振点在扫频上限之上），语音能量正好落在最弱的 30–48 dB 区间——这是「声音小」的根本原因，与换音色 / 换音高无关。据此试过的**共振峰整体上移 1.5 倍（花栗鼠音）**实测只有 **+0.9 dB**（F1 上移后仍在弱区、F3 越过 3.6 kHz 奈奎斯特上限），已放弃作为响度方案，`analysis_sample_rate` 配置项保留备用。
- 验证：`build_voice.ps1` 一条命令串起系统中文 TTS 参考音 → LPC-10 分析量化 → 定点模型校验 → SDCC 固件 → 汇编中断预算检查；其中最硬的两条是把 `voice_synth.c` 编成主机程序与 Python 定点模型逐样本比对（18360 样本 **0 处不同**）、穷举 `mul_q8` / `lerp_q8` 边界（7025 组 0 处不同）。`build.ps1` 同时兼容 Windows PowerShell 5.1 并登记本工程。
- 属仓库侧的示例固件与工具链冒烟工程（不在应用的项目向导里选），**不影响应用内编译出的固件**；设计与复现步骤见 [蜂鸣器 LPC 语音合成示例固件](docs/design/蜂鸣器LPC语音合成示例固件.md) 与 [stc32g_sdcc/README.md](stc32g_sdcc/README.md)。

## 升级提示

- 项目文件格式仍为 **16**，1.3.0 保存的 `.pieproj` 可直接打开，本次没有破坏性格式变更。
- **调试项目需要重填摩擦轮目标占空比**：1.3.0 里摩擦轮项的 `value` 是 0–100 的油门百分比，本版本按目标占空比（500–800）解释，打开旧项目会报「P64/P66 摩擦轮目标占空比必须在 500–800 之间」，请按这张卡实测想跑的占空比重填。旧项目里已不再使用的 `friction_p64_max_duty` / `friction_p66_max_duty` 与 `cue_style` 字段会被忽略。
- **需要重新编译并烧录**才会生效的调试项：测试序列循环执行、每轮开头重发 `Init_Order`、提示音只剩步序（不再有结束回落与《卡农》完成音）、摩擦轮目标占空比的新语义。步兵、工程与音乐固件本次没有生成逻辑上的行为变化。
- 提示音风格：原先选「紧凑」的项目不再有紧凑档，时值固定为标准那一套（单音 220ms / 音间 140ms / 分区停顿 300ms）；标准档用户听到的固件与 1.3.0 逐字节一致。
- **音乐项目不再导出 `main.asm`**：手写汇编输出目标已整体移除。要看汇编请到「生成代码」页点右上角「汇编」，用内置 SDCC 完整构建一次，查看链接后的 `main.rst`（仅桌面版，Web 与 Android 只有 C）。
- 「编译与烧录」页现在叫「**烧录**」；编译在「生成代码」页按需触发。
- Android 上导出生成代码原先必然失败（`File(路径)` 在 scoped storage 下不可写），现在走系统文档选择器；桌面导出多了「浏览」按钮，失败时给 SnackBar 提示而不是静默。

## 已知限制

- Windows 安装包**未做代码签名**，SmartScreen 可能提示「未知发布者」，选择「仍要运行」即可。Linux 侧只提供 tar.gz，未做发行版原生包与桌面集成。
- **汇编列表只在桌面版提供，且必须用内置 SDCC 做一次完整构建**：Web 与 Android 只有 C 代码。点「汇编」始终用内置 SDCC 构建，所以在烧录页选 Keil 也照样能看列表，只是列表与 Keil 的实际产物可能略有差异（Keil 的构建链路本身不产出该列表）。1.3.0 的 `main.asm` 导出与「音乐项目试点直接生成汇编」已移除，四类工程想看汇编都走这条路径。
- **本次没有 Android 安装包**：打 `v*` 标签时 Android 流水线要求仓库配置 `ANDROID_KEYSTORE_*` 发布签名 Secrets，缺失会被 CI 直接拦截；即使有包，Release 构建也没有启用本地编译流水线（`PB_SDCC_PIPELINE_ENABLED` 只在 Debug 构建打开），只能配置、编辑与预览，不能编译固件。Android 的 USB-HID 烧录协议已接入，但受 STC32G ROM ISP 固件对用户态 USB 主机的入场时序限制，真机实测无法烧录。
- Web 版是只读演示：可以配置项目、查看并导出生成的 C 代码（**没有汇编列表**），**不能编译或烧录**。
- 调试提示音靠「数音数 + 分辨八度」辨识：单次最多 5 个音，第 6 项起整体升八度进位；本轮固定十路引脚因此够用，若将来测试项超过 10 步需要再加一个音区。
- 蜂鸣器 LPC 语音示例是 TMS5220 级别的参数（7.2 kHz 采样 + 10 阶 + 100 帧/秒），清晰度够、自然度差；单端 3.3/5 V 直推压电片，赛场噪声下只适合近距离提示。
- 使用 Keil 编译需要本机已安装并授权 Keil C251（仅 Windows）；使用内置 SDCC 则无此要求。
- 主控板为 STC32G（STC32G12K128）。
