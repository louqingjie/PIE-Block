# PIE-Block 1.6.0

界面按 **M3E 设计体系**整体重构（首页、向导外壳、表单、烧录/编译进度与音乐工具栏），并新增分段按钮组、波浪进度条、四态步骤徽标与右下角浮动操作组。生成代码页的汇编列表接入**字段悬停说明**：覆盖 MCS-251 全部 65 个指令族、寄存器元组、段与伪指令、常用 SFR 与位名，并结合 `main.rst` 自带符号表区分同地址的位符号与 SFR。固件编译主频从 33.1776MHz 迁到 **22.1184MHz**，规避个别 STC32G12K128 芯片 33.1776MHz 档出厂校准值损坏导致的「波特率不对 + 全部延时慢 1.46 倍」。Windows 新增**单文件便携版**（约 27MB，免安装、不需要管理员权限），仓库新增主控板主频异常筛板工具与标准流程。

Windows 与 Linux 都内置离线 SDCC C251 工具链与 STC32G 固件模板，**无需另外安装编译器**即可编译并烧录步兵、工程、调试与音乐四类工程。Linux 首次烧录前仍需授权 hidraw 设备，可在应用内「烧录」页一键安装（行为与 1.4.0 起相同）。

Release 同时附带稳定命名副本 `PIEBlock-windows-setup.exe` 与 `PIEBlock-linux-x64.tar.gz`，供官网直链使用（`/releases/latest/download/...`，不随版本号变化）。

**本次 Release 仍不附带 Android 安装包**：打 `v*` 标签时 Android 流水线会强制校验发布签名 Secrets，仓库没有配置，CI 会直接拦截标签构建（这条门禁 1.3.0 起就已存在）；Android 的 Release 构建也仍未启用本地编译流水线（`PB_SDCC_PIPELINE_ENABLED` 只在 Debug 构建打开），只能配置、编辑与预览，不能编译固件。

## 主要变化

**固件主频迁移到 22.1184MHz（必须重新编译并烧录）**

- 背景：个别 STC32G12K128 的出厂校准表里 `CHIPID15`（33.1776MHz 档 IRC 微调值）损坏——本例读到 `0x3D`，按同频段实测刻度（`22.1184M=0x31`、`24M=0x54`、`27M=0x8A`、`30M=0xC2`）线性外推应约 `0xFA`。程序 `System_Clock_Set()` 与 STC-ISP 写选项读的都是这个值，所以「官方重烧 33.1776」也无效，芯片实跑 ≈22.6MHz：UART 230400 变成约 153k~157k（按 230400 读全是乱码），固件里所有 `Ms_Delay` 同步慢约 1.46 倍（3s 保持实测 4.39s）。属芯片级校准数据缺陷，软件无法可靠修复。
- 处置：SDCC（`stc32g_sdcc/`）与 Keil（`stc32g/`）两套运行时的 `FOSC` 由 `33177600` 改为 `22118400`，并同步 4 处 `#if (… == FOSC)` 守卫。其中 `Register_Set()` 里那处若漏改，`System_Clock_Set()` 根本不会执行，芯片会停在 ISP 选项频率、波特率与延时全错。
- 选 22.1184MHz 的理由：`22.1184e6/4/230400 = 24` 整除，230400 精确，9600/115200/460800/921600 同样整除；该档校准值（`CHIPID11`）在故障芯片上实测正常；与 33.1776MHz 同属 27M 频段，`System_Clock_Set()` 里现成有 `case 22118400`，改动最小、余量最大。代价是相对速度 0.667×。
- SDCC 延时按「约 4 周期/次」线性重算：`Delay1000us` 计数 `8293(0x2065)` → `5529(0x1599)`、`Delay1us` `7` → `5`；与 STC 官方延时生成器在 22.1184MHz 给出的 `5528` 交叉校验一致（±1 舍入差）。Keil 侧用 `DELAY_MS/DELAY_US` 自适应，无需改数值。
- 语音示例工程 Timer0 重载 `60928` → `62464`（`65536 − 22118400/7200`，仍为 7200Hz 采样率）；`check_voice_model.py` 的周期预算改为从 `common.h` 读 `FOSC`，避免以后调主频时静默算错。
- 验证：SDCC 16 个工程构建 PASS（含 HEX/MAP 布局校验）、Keil 工程 0 Error；故障板标定固件 `1000/3000/10/1000ms` 实测 `1007.4/3022.8/9.8/1007.5ms`。+0.75% 来自该芯片 22.1184MHz 档的个体误差，波特率误差远小于 8N1 的 ±4% 容差，对拓展板协议无影响。
- 明确不做的两件事：不用 HID 烧录去写硬件选项（应用固件启动会用 CHIPID 重新设频，选项必被覆盖，且误写选项有让芯片进不了下载模式的风险）；不做「运行时自测主频 + 自动改正」（内部唯一独立基准是 32K 低速振荡器，精度约 ±1~3% 且温漂大，会把基准不准的好板一起改坏）。
- 现象量化、探针矩阵、改动清单、延时推导、部署与回滚方案见 [主控板主频故障复盘与 22.1184MHz 迁移](docs/design/主控板主频故障复盘与22.1184MHz迁移.md)。

**主控板主频异常筛板工具与流程**

- `tools/diagnostics/board_clock_screen.py`：阶段 1 快速筛板，按应用固件的 21 字节协议帧判定 230400 是否正常。迁移后判据不变（22.1184MHz 下 230400 依旧精确整除），只是「低档区间」的解释随标称频率变化。
- `tools/diagnostics/board_clock_probe_report.py`：阶段 2 探针判读，读取 `CHIPID15`/`CHIPID23` 并逐档实测实际主频。
- `tools/diagnostics/clock_probe_main.c` + `build_clock_probe.ps1`：Keil C251 探针固件源码与一键构建脚本。探针用于**诊断**「33.1776 档校准值坏」的片子，不作为交付固件。
- `tools/diagnostics/run_screen_batch.ps1`：批量筛板并把结论写入 CSV。
- 完整流程、判定阈值与记录表见 [主控板主频异常筛板流程](docs/playbook/主控板主频异常筛板流程.md)；迁移后关键校准项由 `CHIPID15` 改为 `CHIPID11`（工具与文档已注明，探针固件「增印 CHIPID11、主判据改 CHIPID11」仍列为 TODO）。

**界面：M3E 设计体系重构**

- 迁移到 `material_ui` 与 `MaterialShapes`，新增设计 token、主题与第三方主题桥（`lib/src/design/app_theme.dart` 等）；首页、向导外壳、表单、烧录/编译进度与音乐工具栏按 M3E 重构，并补充设计系统与 `material_ui` 导入约束测试。
- 新增组件：分段按钮组（connected button group）、波浪进度条、形状徽标底座、按压缩放反馈与 `AppCard`。
- 主题统一为品牌青色系：单一青蓝种子 + `tonalSpot` 生成全套色阶，珊瑚粉只保留为首页局部强调色（此前两个种子色各自生成配色再拼接会混出脏色），选中步骤文字改用 `onSecondaryContainer`。
- 向导侧栏步骤序号改为四态状态徽标：已完成显示勾选、当前步实心、下一步与未解锁步骤用空心圆区分，访问进度在侧栏直接可读；窄屏下拉保持不变。
- 向导页脚改为右下角浮动操作组：步骤计数与上一步/下一步收进悬浮操作组，不再占用整条底栏；前进按钮箭头改为尾随，去掉按下放大，只保留 M3E 形变。
- 分段组按 M3E small 档位收敛：组高 48→44、内部按钮回到标准的 40 并撑满组高（选中胶囊不再悬空浮在组里）、图标 18→20。
- 波浪进度条与确定进度解耦：进度停在同一格时波峰仍按「一个波长每秒」向右推进，波形改为行波 `sin(kx − ωt)`，因此填充变长时不再被拉伸；按规范在 10% / 95% 两端收敛振幅，跑满后收成平线并停掉重绘。
- 首页卡片团块背景改由卡片圆角统一裁切（此前被 `AppCard` 的内边距裁在内容区，负偏移的团块贴不到卡片边缘）；CTA 文字与箭头统一使用按钮前景色，不再出现青底白字配黑箭头。

**生成代码页：汇编字段悬停说明**

- 新增汇编术语词表 `lib/src/asm_glossary.dart`：覆盖 MCS-251 全部 65 个指令族与 `call`/`pushw` 别名、R0–R15 及 AR/WR/DR 寄存器元组、asxxxx 段与段属性、伪指令、常用 SFR 与位名，并给出十六进制与十进制的互换算。
- 新增 `AsmListingIndex` 解析 `main.rst` 自带的符号表与标签表：`_TI` 这类位符号能与同地址的 SFR 区分，局部标号可报出定义行与地址。
- 只读汇编编辑器改用带 `spanBuilder` 的控制器工厂：把高亮结果展平成叶段后按字段范围注入 `MouseTrackerAnnotationTextSpan`，样式原样保留，C 视图不启用。悬停 200ms 后在字段旁弹出说明卡片，以等宽字体显示字段原文与类型标签，下面依次是标题、说明与语法/标志/地址补充；空间不足时翻到字段上方、水平方向夹紧在可视范围内；卡片整体 `IgnorePointer`，不抢编辑器上的选择与滚动。滚动、搜索跳转、按下拖选、切换 C/汇编或重新编译时收起；工具栏在汇编栏就绪时加一个提示图标。
- 修复行尾字段无法悬停：`re_editor` 的 `_ParagraphImpl.getSpanForPosition` 在 `offset >= length - 1` 时直接返回 null，每行最后一个字符永远命中不到，而 `clr a`、`rlc a`、`mov r6,a` 的操作数恰好都落在行尾。汇编视图改为交给编辑器「每行补一个尾随空格」的显示文本，段落文本因此变长一格；补在文本里而不是只补在高亮结果里，是因为两者必须等长，否则点行尾空白会得到超出行长度的光标位置。复制、搜索与另存为仍用原始文本。
- 高亮词表改为与悬停词表共享同一份数据，并补齐实际输出里出现但此前未收录的 `sub`、`movz`、`cmp`、`jne`、`sll`、`ab`、`r8`–`r15`、`wr`/`dr`、`psw1`、`.optsdcc`，移除并不存在的 `sla` 与 `dpxh`。
- 汇编编译等待改为就地显示：删除铺满内容区的 90% 遮罩，改在 `main.rst` 将要出现的位置显示确定进度（由 `[7/22]` 换算）、阶段文案与骨架行；占位面板与编辑器共用底色、圆角与高度，工具栏留在原位并禁用，列表到达时内容原地淡入，不会把整块区域顶下去。编译状态改写进页面说明行，翻页入口改为可见的禁用态而不是被遮罩挡住。

**打包：Windows 单文件便携版**

- 新增 `tools/portable_launcher/PortableLauncher.cs`：自解压启动器，把整个 Windows Release 目录以 zip 载荷内嵌进单个 exe，首次启动解压到 `%LOCALAPPDATA%\PIE-Block\portable\app\<版本号+载荷哈希>\`（约 1–2 秒）后启动 `PIE-Block.exe`，之后直接复用缓存；支持参数透传与 Unicode 路径，不需要管理员权限，也不写注册表。诊断开关：`PIEBLOCK_PORTABLE_ROOT` 覆盖解压目录、`PIEBLOCK_PORTABLE_EXTRACT_ONLY=1` 只解压不启动、`PIEBLOCK_PORTABLE_LOG` 指定启动器日志。多实例并发首次启动由按载荷 ID 命名的本地互斥量串行化，超过 1 天的残留 staging 目录会被清理。
- 新增 `tools/package_flutter_windows_portable.ps1`：校验 Release 产物完整性、生成 zip 载荷、用 Windows 自带 .NET Framework `csc` 编译单 exe（输出 `output/PIEBlock-<版本>-windows-portable.exe`，约 27MB）；`-Verify` 以 EXTRACT_ONLY 模式解压自检，不污染用户缓存。
- `windows.yml` 的 Windows 打包阶段会生成便携版并随产物上传，打标签发版时自动作为 Release asset 附带。

**品牌标识**

- 首页显示首都师范大学 **W.PIE 学生创新实验室**完整官方标识；过程页（向导）宽屏步骤栏底部与窄屏步骤栏只展示从同一张图顶部裁出的 **W.PIE 词标**，不再出现“首都师范大学”“学生创新实验室”两行中文，实验室全名只保留在无障碍标签里。浅色主题使用去除白底后的透明彩色原图，深色主题自动切换为同形状的白色单通道版本（`assets/images/wpie-logo-light.png` / `wpie-logo-dark.png`、`wpie-wordmark-light.png` / `wpie-wordmark-dark.png`）；两套资源裁切一致，切换主题时布局不跳动，也不再需要白色底板。

**修复**

- Linux 桌面端卡顿：主题的 `fontFamilyFallback` 原先列出 `Microsoft YaHei UI`、`PingFang SC`、`Source Han Sans SC` 等系统字体族名，其中多数在 Linux 上并不存在，fontconfig 为未知族名会逐个打开全部系统字体建立 typeface（实测一次约 1 万次 `openat`、单帧 1–2 秒），导致首帧、首次打开「新建项目」弹窗、首次进入向导时 UI 线程明显卡住。现改为只回退到随包分发的 3.8KB 符号子集（`assets/fonts/NotoSansSC-Symbols-subset.ttf`，含 `– ÷ ≥ ≤ ♯ ♭ ♮` 等原本缺字），代码列表与烧录日志的字体也由系统 `Consolas` 改为内置 `PieBlockMono`；实测运行期系统字体 `openat` 从约 1 万次降到 10 次量级，弹窗与进入向导不再出现秒级长帧。
- 调试序列拖拽：浮层改为与卡片一致的圆角描边且只对卡片本体投影；调试序列改为独立滚动区，拖拽夹在列表视口内并恢复边缘自动滚动。补充拖拽边界与重排回归测试。

## 升级提示

- 项目文件格式仍为 **16**，1.5.0 及更早保存的 `.pieproj` 可直接打开，配置字段没有增删。
- **必须重新编译并烧录**：`FOSC` 从 33.1776MHz 改为 22.1184MHz，步兵、工程、调试与音乐四类工程的延时、UART 230400 波特率与语音 Timer0 重载全部随之变化。安装版 IDE 编译时用的是**内置固件资产**，1.5.0 及更早安装包里那份仍是 33.1776MHz，装 1.6.0 后重新编译即生效（不想立刻升级也可以用 `PIEBLOCK_RUNTIME_ROOT` 环境变量指向仓库新源码临时验证，见主频复盘文档 5.1 节）。固件源码指纹变更会让旧构建缓存失效一次，升级后首次使用内置工具链时会重新部署一次运行时（约 24MB）。
- 界面整体换装：首页、向导、表单、分段控件与进度指示器的形状、间距、配色与页脚位置都与 1.5.0 不同；操作步骤、字段与生成逻辑没有变化。
- 便携版首次启动需 1–2 秒解压；同一版本 + 同一载荷会复用缓存，换版本会新建一份解压目录，旧目录不会自动清理。应用设置仍保存在系统应用数据目录，配置不随 exe 一起带走。
- 主频降到 0.667× 后，CPU 密集路径的墙钟耗时相应变长：音乐工程的软件 SPI 整屏刷新预计从约 5–10ms 增加到约 7.5–15ms（**未实测**）。`MusicClock` 上电用 `Ms_Delay(10)` 校准 ticks/ms，乐曲节奏按新主频自动适配，但极端快速曲目挤压当前音符发声长度的余量比 1.5.0 更小。

## 已知限制

- Windows 安装包、便携版与免安装 zip **均未做代码签名**，SmartScreen 可能提示「未知发布者」，选择「仍要运行」即可；正式分发前请先签名。Linux 侧只提供 tar.gz，未做发行版原生包与桌面集成。
- Flutter 官方明确不支持把 `flutter_windows.dll` 与 `data/` 静态链接进单个 exe（[flutter#75200](https://github.com/flutter/flutter/issues/75200)），便携版是「自解压启动器 + 本地缓存」方案，不是真正的单文件运行。
- **本次没有 Android 安装包**（发布签名 Secrets 未配置，打 `v*` 标签会被 CI 拦截）；Android 的 USB-HID 烧录协议已接入，但受 STC32G ROM ISP 固件对用户态 USB 主机的入场时序限制，真机实测无法烧录。
- Web 版是只读演示：可以配置项目、查看并导出生成的 C 代码，**不能编译或烧录**。
- 主频迁移后**尚未完成**的验证：语音示例工程在 22.1184MHz 下的听感（125µs 中断预算从 4147 周期降到 2765 周期，若出现破音需把采样率降到 6400/6000Hz 并重算重载）；Keil 侧同款标定固件的板测（构建已生成、0 Error，未烧录核对）；好板基线未采集（建议用 ≥5 块好板跑探针采集 `CHIPID11` 分布，作为新的筛片阈值）。
- 无线 IAP bootloader **未同步**到 22.1184MHz，其波特率与延时仍按 33.1776MHz 计算；启用无线升级功能前必须先同步。
- 本批已确认的故障板建议直接换片（校准数据损坏不可修复），22.1184MHz 迁移的目的是让全系统不再依赖 33.1776 这一档。
- 汇编悬停说明只覆盖词表收录的字段；词表按实际输出的 `main.rst` 校准，固件模板若引入新指令族需同步补词表（已有测试守护词表完整性与「词表 ↔ 高亮」同步）。
- 音乐固件：只有 SDCC 构建包含五线谱显示（Keil 构建仍只有蜂鸣器播放）；只处理第一个拍号事件；三连音等非标准时值按最近标准时值近似、不画连杠；7 个升降号时固定区很挤，实际曲目按 0–4 个升降号使用；必须留在低 64KB（高 64KB 常量区在 ROM USB-ISP 多次烧录后不可靠）。
- 使用 Keil 编译需要本机已安装并授权 Keil C251（仅 Windows）；使用内置 SDCC 则无此要求。
- 主控板为 STC32G（STC32G12K128）。
- 首页与向导的交互手感 P0 项（关闭项目保存失败丢改动、全局快捷键、返回键接管、数字输入受控等）本版本**仍未处理**，清单与证据见 [交互手感评估与改进建议](docs/design/交互手感评估与改进建议.md)。
