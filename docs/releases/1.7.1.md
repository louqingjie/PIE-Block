# PIE-Block 1.7.1

1.7.0 的**修复版**：只修一个实机问题——同一电机引脚配置两行动作时「反向键按下没反应」。本版**不包含 1.8.0 的任何新功能**，存档格式仍是 **17**，1.7.0 的工程文件直接可用。

## 下载

| 文件 | 说明 |
| --- | --- |
| `PIEBlock-1.7.1-windows-setup.exe` | Windows 安装包，双击按向导安装 |
| `PIEBlock-1.7.1-windows-portable.exe` | Windows 单文件便携版，免安装，首次启动自解压约 1–2 秒 |
| `PIEBlock-1.7.1-windows-x64-release.zip` | Windows 免安装版，解压后运行 `PIE-Block.exe` |
| `PIEBlock-1.7.1-linux-x64.tar.gz` | Linux 免安装版，解压后运行 `pieblock_app` |

Windows 与 Linux 都内置离线 SDCC C251 工具链与 STC32G 固件模板，**无需另外安装编译器**即可编译并烧录步兵、工程、调试与音乐四类工程。Linux 首次烧录前仍需授权 hidraw 设备，可在应用内「烧录」页一键安装。

**本次 Release 仍不附带 Android 安装包**：原因同 1.7.0，仓库未配置发布签名 Secrets，打 `v*` 标签时 Android 流水线会拦截。

## 修复

**同一引脚多行动作互相清零：「反向键按下没反应」**

- **现象**：工程模式下，同一模式里两行动作输出到同一个电机引脚（例如 B 反向、C 正向）。按住正向键正常，按住反向键电机不动。
- **原因**：每行各自生成 `dutyOfMotor[slot] = 按下 ? 值 : 0`；后一行的按键没按下时，会把前一行刚写入的值清成 0。
- **修复**：同一槽位的多条「直接」行按行序合并成一条 `if / else if / else` 链，行序在后的优先，全部松开才归零。只配一行的工程，生成代码逐字节不变（6 个金样的生成源码 SHA-256 未变）。
- **仍然是按行序覆盖的组合**（「直接」与「速度／增速」混用、两条表达式行写同一引脚）行为不变，但校验器会在「检查与摘要」里给出「在本模式被多行输出」的提醒。
- **验证**：新增单元用例与 `eng-motor-direct-two-keys` 运行时场景；修复前该场景报「反向键按住期间占空比应为 10000（得到 0）」，修复后通过。

## 升级提示

- **存档格式仍是 17**：1.7.0 保存的 `.pieproj` 直接打开即可，不需要迁移。
- **用了「同一引脚多行输出」的工程必须重新生成并烧录**：旧固件里仍是旧的清零逻辑，只升级软件、不重新烧录不会生效。
- 本版不含 1.8.0 的按键动作表、摩擦轮全输出脚、方向正负号、引脚备注与增量编译；需要这些功能请使用 `1.8.0-beta.1`。两个版本可以并存安装，工程文件互不冲突。

## 已知限制

- Windows 安装包、便携版与免安装 zip **均未做代码签名**，SmartScreen 可能提示「未知发布者」，选择「仍要运行」即可；Linux 只提供 tar.gz，未做发行版原生包与桌面集成。
- **本次不提供 Android 安装包**（发布签名 Secrets 未配置）。
- Web 版是只读演示：可以配置项目、查看并导出生成的 C 代码，**不能编译或烧录**。
- 使用 Keil 编译需要本机已安装并授权 Keil C251（仅 Windows）；使用内置 SDCC 则无此要求。
- 教材示例工程不承诺适配具体车体：引脚分配、电机方向、舵机中位都要按实车重新核对后再烧录。
