# PIE-Block 1.2.1

修复 1.2.0 用 SDCC 编译的固件与拓展板通信错帧的问题（实机验证通过），并把调试工程的摩擦轮测试对齐步兵的斜坡与蜂鸣行为。

## 下载

| 文件 | 说明 |
| --- | --- |
| `PIEBlock-1.2.1-windows-setup.exe` | Windows 安装包，双击按向导安装 |
| `PIEBlock-1.2.1-windows-x64-release.zip` | Windows 免安装版，解压后运行 `PIE-Block.exe` |
| `PIEBlock-1.2.1-linux-x64.tar.gz` | Linux 免安装版，解压后运行 `pieblock_app` |

三种形态都内置离线 SDCC C251 工具链与 STC32G 固件模板，**无需另外安装编译器**即可编译并烧录步兵、工程、调试与音乐四类工程。Linux 首次烧录前仍需按 1.2.0 的说明安装 hidraw udev 规则。

## 主要变化

**修复：SDCC 固件与拓展板通信错帧（实机验证）**

- 现象：同一份固件源码，用 Keil 编译能正常和拓展板通信，用 SDCC 编译不通。
- 根因：生成固件的组帧函数采用 `uint16_t values[8]` + `control_frame_pack[3+i*2] / [4+i*2]` 的写法，SDCC 的 MCS251 后端在这个组合上把**低字节位置写成了高字节**——10000Hz 发成 `0x2727`、占空比 500 发成 `0x0101`，拓展板收到错误的频率与占空比后不动作。
- 修复：改为与《RM电控指南》参考实现一致的**逐字展开**写法（直接从形参取高/低字节），步兵、工程、调试三类生成固件以及调试工程的 `FrictionSendDuty` 一并改掉。
- 验证：重新生成并烧写后，用 USB 转串口在 P31 抓包（230400 8N1）恢复成 `27 10`、`01 F4` 等正确配对，拓展板通信正常。
- 排查过程、根因证据与后续规避要点记录在 [docs/pitfall/sdcc-组帧低字节丢失.md](docs/pitfall/sdcc-组帧低字节丢失.md)。

**调试工程：摩擦轮测试行为对齐步兵**

- 蜂鸣频率改为等于摩擦轮当前占空比：启动斜坡爬升即为一路上行的扫频提示音。
- 斜坡控制与步兵同律：按主循环周期 ±1 duty 逼近，静止启动先跳到 500 启动占空比，目标为 0 且已降到 500 及以下时直接停机。
- 每个摩擦轮测试项只设一个目标占空比（油门比例值按该引脚自己的满油上限换算），斜坡到位后停留 1.5s 观察，再设目标 0 停机。
- 不再发送方向帧（摩擦轮方向固定），测试期间只做占空比渐变。
- 拓展板不再逐个测试项重复初始化：`Init_Order` 只在 PWM 组频率（电机 10000Hz / 舵机与摩擦轮 50Hz）需要切换时才发送。
- 新增激活阶段：先给 500 启动占空比并保持 500ms 让电调完成激活，**这段时间不发声**。

## 升级提示

- 项目文件格式仍为 **16**，1.2.0 保存的 `.pieproj` 可直接打开使用，本次没有格式变更。
- 使用内置 SDCC 编译并烧录的同学请务必更新到本版本：1.2.0 生成的 SDCC 固件存在上述错帧问题，双编译器（Keil）产物不受影响。
