# PIE-Block 1.5.0

音乐工程是本次更新的主线：钢琴卷帘支持**音符重叠**，按「取高音 / 取低音 / 取最近音阶 + 新音符打断」做**单音裁决**，并新增 Ctrl+A / Ctrl+C / Ctrl+V 与多选整组拖动；音乐工程用内置 SDCC 编译时，固件会在 128×64 OLED 上**滚动显示五线谱**，并用 Timer0 轮询时基补偿刷屏耗时、恢复乐曲原速。首页最近项目按类型显示图标，新建项目时名称与文件名实时同步；修复中文用户名下 SDCC 链接后编译失败、首次部署内置工具链被杀毒软件占用失败等问题；仓库新增面向大学生的 LaTeX 教材骨架与第一、二章正文初稿。

## 下载

| 文件 | 说明 |
| --- | --- |
| `PIEBlock-1.5.0-windows-setup.exe` | Windows 安装包，双击按向导安装 |
| `PIEBlock-1.5.0-windows-x64-release.zip` | Windows 免安装版，解压后运行 `PIE-Block.exe` |
| `PIEBlock-1.5.0-linux-x64.tar.gz` | Linux 免安装版，解压后运行 `pieblock_app` |

Windows 与 Linux 都内置离线 SDCC C251 工具链与 STC32G 固件模板，**无需另外安装编译器**即可编译并烧录步兵、工程、调试与音乐四类工程。Linux 首次烧录前仍需授权 hidraw 设备，可在应用内「烧录」页一键安装（行为与 1.4.0 相同）。

Release 同时附带稳定命名副本 `PIEBlock-windows-setup.exe` 与 `PIEBlock-linux-x64.tar.gz`，供官网直链使用（`/releases/latest/download/...`，不随版本号变化）。

**本次 Release 仍不附带 Android 安装包**：打 `v*` 标签时 Android 流水线会强制校验发布签名 Secrets，仓库没有配置，CI 会直接拦截标签构建（这条门禁 1.3.0 起就已存在）；Android 的 Release 构建也仍未启用本地编译流水线（`PB_SDCC_PIPELINE_ENABLED` 只在 Debug 构建打开），只能配置、编辑与预览，不能编译固件。

## 主要变化

**音乐项目：固件在 OLED 上显示滚动五线谱**

- 音乐工程用内置 SDCC 编译时，生成的固件在 128×64 单色 OLED 上滚动显示五线谱：左端固定区是谱号（按音域自动切换高/低音谱号）、调号与拍号，右侧按 tick 滚动，当前播放位置用谱表上方的 ▼ 标记。
- 支持加线、符干与符尾、附点、临时升/降/还原号、休止符与跨小节还原；音高位置按调号拼写后的音名计算（例如 F 调里 MIDI 68 记在 A 间写 Ab，不会画成 G 线的 G#）。
- 乐谱事件、字形点阵与调号/拍号表全部由 `pieblock_core` 预计算后随 `main.c` 发射（SoA 事件表），固件只做几何绘制与整屏刷新。新增 `StaffRender.c`（纯 C，可主机 gcc 编译）、`OLED_Staff.c`（1024B XRAM 帧缓冲）与 `LCD_Frame.c`（软件 SPI 整屏写），不修改厂商 `LCD.c`。
- 离线模拟器 `tool/render_oled_staff.dart` 与固件共用同一套整数版面，6 个场景 66 帧主机对拍逐字节一致；fixture 与漂移检查已随仓库提交。方案、限制与固件接入细节见 [OLED 五线谱显示方案](docs/design/OLED五线谱显示方案.md)。
- 调号成为音乐工程的可编辑配置（`key_signature_fifths`，-7…7，默认 0=C 大调）：卷帘工具栏可直接选 15 个调，MIDI 导入/导出读写 0x59 调号 meta。

**音乐项目：刷屏不再拖慢乐曲**

- 整屏刷新一次约 5–10ms，直接叠加在 `Music_Wait` 上会让整曲慢 2–4%（982 个显示事件的曲目慢 5–10 秒）。新增 `MusicClock.c`：Timer0 16 位自由计数，按绝对截止时间调度「到点发声 → 整屏刷新 → 推进到下一个累计时值」，刷新与当前音符的时值重叠，最后一个音符等满时值再停。
- 时钟**刻意不使用定时器中断**：SDCC 的 ISR 入口不保存 DPXL，中断落在主循环 `MOVC`/`@DPX` 指令间隙时会破坏代码/XDATA 访问，真机表现为闪屏、不播放与蜂鸣器周期性咔哒。改为纯轮询（渲染后、刷屏后各补一次采样，保证间隔远小于 23.7ms 溢出周期），上电用 `Ms_Delay(10)` 校准 ticks/ms，计时器失效时自动退回旧节奏。
- 试过把只读常量搬到高 64KB（`0xFF1000` 之后）把可用 flash 扩到 128KB，但 ROM USB-ISP 对高区的擦除/写入在多次烧录后不可靠（重烧后开机 logo 图案异常、五线谱卡首帧），已回退：音乐固件的代码、常量与五线谱事件表全部留在低 64KB。校验器按「约 50KB 基础 + 11B/事件」估算，超过约 61KB 时告警（不阻止生成）。
- Keil 音乐构建保持原蜂鸣器播放，不含五线谱显示；部署页会给出提示。

**音乐项目：卷帘编辑**

- 音符允许重叠。同一 tick 起始的一组音符按「重叠处理」策略只发声一个：取高音、取低音或取最近音阶（以之前最后有效发声的音高为参照，曲首没有参照时取最高音）；勾选「新音符打断」后，后起始的音符会打断仍在发声的音符，被打断的尾巴不发声。不发声的音符/片段在卷帘里显示为灰色，数据仍完整保留并参与 MIDI 导出。
- 工具栏新增「重叠处理」下拉、「新音符打断」开关与「N 处重叠」徽标；拖动、调时值、画笔新建与粘贴不再拒绝重叠，产生重叠时给一次提示。
- 快捷键：`Ctrl+A` 全选、`Ctrl+C` 复制选区（按最小时刻归一化）、`Ctrl+V` 粘贴到播放头并吸附当前网格；多选后可整组拖动平移（按 tick≥0 与音高 1–127 夹取）。
- 拖动手感修复：位移按按下时指针位置计算，不再起拖跳一下；右缘调时值的命中区按音符宽度自适应 3–10px 且只对单选生效；铅笔模式可拖动按下时已选中的音符；撤销快照延后到拖动真正生效，点击与无位移拖动不再占用撤销历史。
- 播放与暂停合并为单个键：停止时显示播放、播放中显示暂停、暂停后同一键显示「继续」并从暂停位置恢复；修复播放中父级重建后停止键停不掉最初播放实例、声音继续的问题。
- 删除 `primary`/参考音符概念：所有音符都是可编辑、可发声候选，旧工程里的 `primary` 字段被忽略。

**首页**

- 新建项目弹窗：「项目名称」与保存文件名实时双向同步——改名称只换文件名并保留目录，改路径从文件名回填名称，通过「浏览」选文件同样回填；名称已带 `.pieproj` 时不重复追加。Android 的保存位置来自只读 SAF 选择器，只做选中后回填，改名不会重命名文档；Web 无保存位置输入框，行为不变。
- 项目名称只剩空白字符时禁用「创建项目」，避免点击后静默无响应。
- 最近项目按项目类型显示图标（步兵游戏手柄、工程机械臂、调试烧杯、音乐钢琴）；项目类型随设置保存，旧版只存路径的设置会在启动时补读项目文件完成迁移，文件缺失或损坏时退回通用图标；最近项目为空时整块隐藏。
- 设置恢复与最近项目加载做了并发合并与串行写盘，避免旧快照覆盖新状态；记录路径统一去掉首尾空白。

**界面与动效**

- 新增 `m3Duration` 统一 M3 时长与曲线 token：向导步骤切换改为 fade-through，首页到编辑页转场改用 `emphasizedDecelerate` + `medium2`，字段高亮与滚动定位同步对齐；系统开启「减少动态效果」时直接切换，并补充对应测试。
- 向导 `wizard_screen.dart` 按职责拆成 11 个 part 文件（保留单一库与私有符号可见性，不改行为）；整数与小数输入组件合并为泛型 `_NumberField<T extends num>`，共用焦点绑定、字段定位与错误装饰。

**工具链与固件构建**

- 修复中文用户名下链接后编译失败：SDCC/ASlink 按系统 ANSI 代码页写 MAP 的 Files Linked 段，Keil 日志同样可能含 ANSI 路径，旧代码严格按 UTF-8 读取会抛 `FileSystemException`。改为宽松解码工具链文本，并补充 GBK MAP 回归测试。
- 修复首次编译「内置 SDCC 工具链部署失败 / 拒绝访问」：烧录页与生成代码页的两个构建器可能并发部署，杀毒软件也会占用刚复制的 exe，目录 rename 因此失败。部署改为进程内串行 + 唯一暂存目录，晋升 rename 退避重试且只清理不可用目标；构建产物原子写入同样加入文件占用重试；失败时提示关闭杀毒、加白名单或删除目录。
- 固件源码内容纳入构建与部署指纹：之前只哈希清单文件，只改 `.c` 实现的修复（例如把 MusicClock 从中断改成轮询）既不会让构建缓存失效，也不会重新部署运行时，应用会继续烧旧固件。现在对 `stc32g_sdcc` 源码树做内容哈希（排除 `build/`、`__pycache__`、`.git` 等生成目录），构建缓存 schema 升到 v5。

**教材与文档**

- 新增 [book/](book/README.md)：基于 ElegantBook v4.7 的 LaTeX 教材骨架（封面、10 章正文与 3 个附录占位、Windows/Linux 编译脚本、Overleaf 用法），第一章「PIE-Block 概述」与第二章「编译和烧录」已有正文初稿。
- 新增 [OLED 五线谱显示方案](docs/design/OLED五线谱显示方案.md) 与 [中文用户名与首次部署 SDCC 失败](docs/pitfall/中文用户名与首次部署SDCC失败.md) 两篇文档。
- 同步更新 [编译与烧录指南](docs/guides/Flutter编译与烧录指南.md)（修正 runtime/builds 实际路径为 `%APPDATA%\com.wpie\PIE-Block`，补充中文用户名与工具链占用两条排障）、[项目文件格式](docs/reference/Flutter项目文件格式.md)（重叠裁决与调号字段）、[stc32g_sdcc/README.md](stc32g_sdcc/README.md)（五线谱固件接入与高 64KB 限制）与 README 的音乐项目说明。
- 新增 `tools/run_windows.ps1` 与 `tools/run_windows.cmd`：仓库目录或构建产物被沙箱打上低完整性标签时，把 runner 重新标记为 Medium 再执行 `flutter run`，避免以 Low 进程运行导致写不了 `%TEMP%`、保存不了桌面上的 `.pieproj`；`.cmd` 可双击直接运行，其余参数原样透传。

## 升级提示

- 项目文件格式仍为 **16**，1.4.0 及更早保存的 `.pieproj` 可直接打开。
- 音乐项目新增三个可选字段：`overlap_mode`（默认 `nearest`）、`new_note_interrupts`（默认 `true`）、`key_signature_fifths`（默认 `0`）。旧工程缺这些字段时按默认值处理；旧工程里的 `primary` 字段会被忽略。
- 需要重新编译并烧录才会生效：音乐工程的三项改动——OLED 五线谱显示、MusicClock 播放节奏、重叠裁决后的固件发声。固件源码指纹变更会让旧构建缓存失效一次，升级后首次使用内置工具链时会重新部署一次运行时（约 24MB）。
- 使用 Keil 编译音乐工程仍只有声音、没有五线谱；要看五线谱请用内置 SDCC。步兵、工程、调试工程本次生成逻辑没有行为变化。
- 曲目较长时五线谱事件表可能逼近低 64KB 上限，校验器会给告警，建议缩短曲目或减少音符。
- 首页与向导的交互手感问题（关闭项目保存失败丢改动、全局快捷键、返回键接管、数字输入受控等 P0 项）本版本**没有处理**，清单与证据见 [交互手感评估与改进建议](docs/design/交互手感评估与改进建议.md)。

## 已知限制

- Windows 安装包**未做代码签名**，SmartScreen 可能提示「未知发布者」，选择「仍要运行」即可。Linux 侧只提供 tar.gz，未做发行版原生包与桌面集成。
- **本次没有 Android 安装包**（发布签名 Secrets 未配置，打 `v*` 标签会被 CI 拦截）；Android 的 USB-HID 烧录协议已接入，但受 STC32G ROM ISP 固件对用户态 USB 主机的入场时序限制，真机实测无法烧录。
- Web 版是只读演示：可以配置项目、查看并导出生成的 C 代码，**不能编译或烧录**。
- 音乐固件：只有 SDCC 构建包含五线谱显示；只处理第一个拍号事件（中途变拍号仍按第一拍号画小节线）；三连音等非标准时值按最近标准时值近似、不画连杠；7 个升降号时固定区会很挤，实际曲目按 0–4 个升降号使用；软件 SPI 整屏刷新需数毫秒，极端快速曲目可能挤压当前音符的实际发声长度（后续长音/休止会追回落后的时间）。
- 音乐固件必须留在低 64KB：高 64KB 常量区在 ROM USB-ISP 多次烧录后不可靠，已回退该方案。
- 使用 Keil 编译需要本机已安装并授权 Keil C251（仅 Windows）；使用内置 SDCC 则无此要求。
- 主控板为 STC32G（STC32G12K128）。
