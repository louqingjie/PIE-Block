# PIE-Block 1.9.0

1.9.0 是 1.8.1 之后的功能版本：新增 **AI 改动提案-确认流程**、随安装包发布的 **`pieblock-cli` 命令行工具**，以及步兵/工程主循环的 **十路 IO 状态分类回传**；同时随仓库发布配置 / 排障两个 Agent Skill 和 DSH 插件等配套资料。存档格式保持 **23**，从 1.8.1 升级不改变已有工程语义；从 1.8.0 及更早升级会一并完成 1.8.1 的格式 23 迁移。

## 下载

| 文件 | 说明 |
| --- | --- |
| `PIEBlock-1.9.0-windows-setup.exe` | Windows 安装包，双击按向导安装 |
| `PIEBlock-1.9.0-windows-portable.exe` | Windows 单文件便携版，免安装，首次启动自解压约 1–2 秒 |
| `PIEBlock-1.9.0-windows-x64-release.zip` | Windows 免安装版，解压后运行 `PIE-Block.exe` |
| `PIEBlock-1.9.0-linux-x64.tar.gz` | Linux 免安装版，解压后运行 `pieblock_app` |

产物文件名与标签一致：`PIEBlock-1.9.0-*`（构建号 16）。Windows 与 Linux 都内置离线 SDCC C251 工具链与 STC32G 固件模板，**无需另外安装编译器**即可编译并烧录步兵、工程、调试与音乐四类工程；Linux 首次烧录前仍需授权 hidraw 设备，可在应用内「烧录」页一键安装。

**本次 Release 不附带 Android 安装包**：仓库未配置发布签名 Secrets，`v*` 标签的 Android 流水线会被签名门禁拦截，不会用 debug 签名冒充正式版。Android 版仍只支持配置、编辑与预览，不能在本机编译固件。

## 主要变化（自 1.8.1 起）

### AI 改动提案-确认流程

- 外部 AI / 脚本用 `pieblock-cli propose <工程> --config <候选>` 生成 `<工程>.proposed`，**不直接改工程**；
- 应用检测到提案后显示「AI 提交了改动提案」横幅，可查看字段级差异，用户确认后才写入 `.pieproj`；应用仍是工程文件的唯一写者；
- 候选只需要改正要改的字段：提案只拒绝**新引入**的 error 级校验问题，未配置完的工程也能接收提案；应用前校验 base SHA，避免覆盖用户已保存的改动；
- 应用后 6 秒内可「撤销」回应用前状态；用户再次编辑或切换工程后撤销入口失效。

### `pieblock-cli` 命令行工具

- 随安装包附带独立可执行文件（`cli/pieblock-cli.exe` / `cli/pieblock-cli`），无需 Dart SDK；
- 命令：`validate`（JSON 校验）、`codegen`（输出 C 源码）、`propose`（提交改动提案）、`describe`（机器可读契约）；
- stdout 只放机器可读数据、stderr 放人类可读信息；退出码 0–6（2 校验失败、3 IO/格式错误、6 已有待处理提案需 `--force`）；
- `describe` 新增 `release`（对应 PIE-Block 应用发布版本）与 `formatVersion`（工程格式版本），便于 AI 比对版本；
- 免安装版首次启动会把 `cli` 目录加入当前用户 PATH（只加一次，旧目录自清理）；便携单文件版不写 PATH。

### 十路 IO 状态分类回传（机器人→遥控器协议变化）

- 步兵/工程主循环按 5 次分频（首次立即发送）把 P60/P62/P64/P66/P74/P75/P76/P77/MP03/MP74 的当前输出打包成 20 字节小端载荷，经 NRF 发给遥控器；
- 舵机回传角度、电机/摩擦轮回传有符号 duty、没有输出的脚回传 0；调试与音乐工程不发送；
- **这是载荷协议变化**：机器人固件与遥控器/接收端需要配套更新，只升级一端可能显示不正确。仓库内没有真机/接收端的自动化验证，首次使用请先台架确认。

### 配置 / 排障 Agent Skill 与分发（配套资料，不改变应用运行）

- 仓库新增 `skills/pieblock-config`（按自然语言填写工程参数、生成候选并 `propose`）与 `skills/pieblock-troubleshooting`（对照参数与生成代码排障）；两者都禁止直接改 `main.c`、绕过代码生成器、自行编译/烧录固件；
- DSH 用户可在插件页输入 [`pieblock-dsh-skills`](https://www.npmjs.com/package/pieblock-dsh-skills) 安装，装一次全局生效；
- WorkBuddy 专家包原型位于 `workbuddy-expert/`；源码与示例新增 Gitee 镜像 <https://gitee.com/louqingjie/pie-block>。

### 修复与改进

- 包含 1.8.1 的底盘转向 / 云台俯仰与偏航灵敏度，以及工程舵机动作角度按中位两侧行程放宽的修复；
- 新增参数校验、引脚占用、按键冲突与跨模式静态检查的回归用例（Flutter 测试 393 条通过、9 条环境相关跳过；core 308 条、hid 13 条、toolchain 27 条通过）；
- `flutter analyze`、三个 Dart 包的 `dart analyze` 全部通过；CI 质量门禁与 1.8.x 一致。

## 升级提示

- **1.8.1 → 1.9.0**：存档格式不变（23），打开旧工程直接可用；十路 IO 回传需要把遥控器/接收端一起更新。
- **1.8.0 及更早 → 1.9.0**：会一并升级到格式 23。灵敏度字段缺省为 `100`（旧版行为），未改动灵敏度时生成代码与旧版逐字节一致；格式 23 文件无法被支持到格式 22 的旧版应用打开，会提示升级。
- **Android**：Release 仍不附带安装包（签名 Secrets 未配置），可配置、编辑与预览，不能在本机编译固件。
- **TUI**：TUI 是独立的 `0.1.0` 发布线，不在本 Release 的安装包内；其人工验收（含真机烧录）完成后单独发布。

## 已知限制

- 十路 IO 回传的真机 / 接收端显示未在仓库内自动验证；
- AI 提案流程需要用户在应用里确认才会写入工程；CLI 不编译、不烧录；
- 云端编译、串口/蓝牙烧录、3D 仿真仍未提供；
- Android 版不能编译固件，烧录受固件入场时序限制暂不可用。
