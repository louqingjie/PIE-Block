# 调试模式蜂鸣器提示音方案

> 状态：**已实施**，本文档与代码实况一致
> 相关代码：`packages/pieblock_core/lib/src/code_generator.dart` 的 `_debug()`、曲谱 `packages/pieblock_core/lib/src/debug_cues.dart`
> 最近变更：调试序列改为**循环执行**（跑完最后一项自动回到第 1 项），并移除《卡农》「全部完成」收尾旋律与它的试听按钮 —— 见文末「变更记录」。

## 1. 现状与问题

调试工程按 `tests` 顺序逐项执行（每个启用的引脚一个测试项，默认 3s，项间间隔 1s，最多 10 项），跑完最后一项回到第 1 项循环。改造前提示音：

| 时机 | 旧实现 | 听感 |
| --- | --- | --- |
| 每个测试项开始 | `Beep(500, 200)` | 平音一声 |
| 每个测试项结束 | `Beep(700, 200)` | 平音一声 |
| 摩擦轮激活 1000ms | 静音（PWM duty=0） | — |
| 摩擦轮斜坡 | 蜂鸣频率 = 当前占空比 | 上行扫频（连续量） |
| 全部完成 | `Beep(700, 500)` 每 2s 循环 | 平音一声 |

问题：

1. **步序无编码**。每个测试项的开始音、结束音完全相同，用户只能靠数"嘀"推断进度；一旦走神即错，且无法区分"第 2 步开始"与"第 5 步结束"。
2. **轮廓缺失**。500Hz 与 700Hz 均为平音，仅差 200Hz；而无源压电蜂鸣器在 ~500Hz 附近响应弱、音量小，赛场噪声下更难分辨。
3. **事件类型少且听感接近**。"开始 / 结束 / 全部完成"三类中，后两类都是短平音，缺少身份感。

## 2. 硬件可控维度

蜂鸣器为 P33 无源蜂鸣器，由 `PWM_SET_Frequency(BUZZER_CH, freq, 5000)` 驱动：

- 可控：**音高**（频率）、**节奏**（通断时值）、**旋律轮廓**（音高升降走向）。
- 不可控：音量、音色（单音方波）。

因此区分度设计只能围绕"音高 × 节奏 × 轮廓"展开，不追求音色变化。

## 3. 方案：一条上行音型贯穿全局

**总原则：每项提示只播它自己的序号，不播任何不携带新信息的声音。**

上行音型取 C6-E6-G6-C7-E7（十二平均律，A4=440Hz；前三音是原本的大三和弦分解，后两音按同一三度叠置续上，凑足 5 个音）：

| 层 | 取用方式 | 轮廓 |
| --- | --- | --- |
| 步序（第 N 项） | **音型的前 N 个音**，220ms/音、间隔 140ms | 上行 N 音（个数即序号） |
| 结束音 | **无**——不给「这一项结束」单独发声（理由见 3.2） | — |

听感上每项就是一小段上行「哆 咪 嗦…」，**几个音就是第几项**。

这解决了旧版"反复滴滴声与上行音乐不协调、显得突兀"的问题——步序不再是插进来的滴滴声，而是音型的自然截取。

> **为什么没有「开始区」**：早期版本在步序之前还播一遍完整音型（C6-E6-G6-C7-E7）当作 READY 前奏，但**个数本身已经承载了序号信息**，再播一遍完整音型只是把同一句话说了两遍，还把每项提示凭空拉长 1 秒多（约 1.6s）。既然提示音是"听到几声就是第几项"，前奏就是纯冗余，已删除。连带删掉的还有它的时值宏 `CUE_EVENT_NOTE_MS`。

各层音高：

| 层 | 音高序列 |
| --- | --- |
| 音型（供截取，不单独播） | 1047 1319 1568 2093 2637 |
| 步序 第 3 项 | 1047 1319 1568 |
| 步序 第 6 项（升八度） | 2094 |

### 3.1 音区（八度）负责进位

`zone = (N - 1) / 5` → 项 1~5 用低八度那组（1047 起），项 6~10 用高八度那组（2094 起）。八度是普通人最易分辨的音程，也是半音/全音阶梯最鲁棒的选择（蜂鸣器频率随温度与 PWM 粒度有偏差）。

| 步序 | 音区 | 上行音数 | 听感 |
| --- | --- | --- | --- |
| 1 | 低 | 1 | 哆 |
| 2 | 低 | 2 | 哆 咪 |
| 3 | 低 | 3 | 哆 咪 嗦 |
| 4 | 低 | 4 | 哆 咪 嗦 哆′ |
| 5 | 低 | 5 | 哆 咪 嗦 哆′ 咪′ |
| 6 | 高 | 1 | 哆′（八度跃升，一听即知进位） |
| 7 | 高 | 2 | …… |
| 10 | 高 | 5 | 高八度完整音型 |

**音数上限 5**：人类可靠计数约 4–5（subitizing + 瞬时计数）。超过 5 用八度"进一位"，即电话区号式编码；若将来超过 10 步，再加一个音区（如 4186Hz）即可扩展到 15 步。

### 3.2 为什么没有结束音

早期版本在动作之后再播一段「同一音型跳过落音后倒序」的回落乐句，当作"这一项做完了"的收尾。它已被整体删除：

- **信息量为零**：回落按定义就是上行音型的倒序去尾（第 N 项上行几个音，回落就是去掉落音后的倒序），不可能携带上行没说过的信息——序号与音区都在那段上行里。
- **成本比整套编码还高**：实测 10 项一轮里上行合计 9400ms，而回落 6520ms，外加专为它留的 3000ms 分区停顿——**合计 9520ms，比序号编码本身还贵**。序列现在是无限循环，这 9.5s 每轮都要付，还推迟了"再回到第 N 项"的时间。
- **两个退化项**：项 1 与项 6 跳过落音后为空，回落只能退回音型首音，与步序落音同音高，需要在交界处靠音区硬分。
- **与摩擦轮项的第二段下行撞车**：摩擦轮回零时蜂鸣频率跟着占空比往下扫（这是真实过程量），紧接着再播装饰性回落，两者会糊在一起。

"这一项做完了"改由三件事共同表达：动作本身停下来（电机停转、舵机回位、摩擦轮斜坡归零）、随后的 1s 静默（`TEST_GAP_MS`）、以及下一项重新开始的上行。

### 3.4 过程量编码（保留摩擦轮扫频）

摩擦轮斜坡期间蜂鸣频率 = 当前占空比（现有行为），编码的是**连续油门量**而非事件，与离散的步序/事件音不在同一时间平面，不冲突，保留。激活期 1000ms 静音也保留——它本身即可作为"即将扫频"的可辨识信号。

### 3.5 视觉冗余（本次未做，有明确理由）

共享运行时的 `LedShow()` 只有 3 位（P3^5/6/7），可表示 0–7，而调试序列最多 10 项——步 8/9/10 会回绕成 0/1/2，**恰好在最需要区分的区间引入歧义**，因此本次不纳入。若日后要做，应先增加显示位数（如改用 4 位或双位闪烁），而不是直接复用 `LedShow(step & 0x07)`。

替代方案是把辨识负担放在文案上，但文案只在真正需要它的地方出现：调试页顶部原先的三条说明 banner 已按用户要求全部删除（摩擦轮激活/斜坡说明、提示音口诀、满油上限说明），试听面板的说明段也删了，口诀现在只由按钮标签表达——「第 N 项 / 低·高音区 · 上行 N 声」，「点一下听这一项的提示音」。

### 3.6 序列循环执行：没有「全部完成」这一档

固件把**整段测试序列**放进 `while (1)`：跑完最后一项后留 1s 静默（`TEST_GAP_MS`，与项间间隔同长），八路占空比归零，再把 PWM 组频率复位到 main 起始的 50Hz，然后回到第 1 项。

- **为什么每轮都要重发那条 `Init_Order`**：逐项的那条 `Init_Order` 是**生成期**按"上一项之后应该是什么频率"静态判断出来的（只有组频率变化时才发）。只有每轮都从同一个已知状态起步，这条静态判断在第二轮及以后才继续成立；否则上一轮末尾停在 10000Hz 的那一组会让下一轮的项用错频率。
- **为什么没有轮次提示音**：循环边界就是"第 1 项的一声"——个数即序号，听到 1 声就知道新一轮开始了；1s 静默已经把它和项间切换区分开。若日后觉得不够明确，再加一段轮次标记音。
- 《卡农》「全部完成」收尾旋律已删除：序列不再有终态，也就不需要"全部完成"的提示；连带删掉曲谱数据与它的试听按钮（见「变更记录」）。

## 4. 单步与整轮时间线

单步提示只有**一段**：上行 N 音，随后 300ms 静默（`CUE_SECTION_GAP_MS`）与测试动作隔开：

```
[步序 上行 N 音 ≤1.7s] ─停顿 300ms─ [测试执行 durationMs] ─项间 1000ms─
```

整轮则是把这些项首尾相接，最后一项之后的 1000ms 直接接到下一轮：

```
[第 1 项] ─1s─ [第 2 项] ─1s─ … ─1s─ [第 N 项] ─1s─ 八路归零 + 组频率复位(20ms) ─→ 回到第 1 项
```

停顿是必需的：测试动作的噪音会盖掉步序音，动作前留 300ms 才能让"上行 N 声"完整听清。项与项之间用 1000ms（`TEST_GAP_MS`），既明显长于 300ms，也明显长于步序内部的 140ms，所以"新的一项开始了"听得出来。

提示音开销（只剩上行）：第 1 项 220ms，第 3 项 940ms，第 5/10 项 1660ms，外加动作前的 300ms 停顿。删除开始区（约 −1.6s/项）与结束回落（10 项一轮约 −9.5s）之后，提示音对测试节奏的占用已经很小。

时值只有一套，集中在 `DebugCues` 的常量里：`unitMs` 220、`gapMs` 140、`sectionGapMs` 300。若嫌偏长就改这几个数值（固件与试听同时跟随），**不再提供风格切换**——原先的「标准 / 紧凑」两档与项目字段 `cue_style` 已删除。

## 5. 不同辨识难度的兼顾

| 用户弱项 | 本方案的兜底 |
| --- | --- |
| 音高记忆弱 / 四音不全（约 4% 人群） | 个数计数 + 上行轮廓不依赖音高记忆；音区只要求分辨八度 |
| 计数弱 / 容易走神 | 音数 ≤5；音区给出粗区间；错过可等下一轮重新同步（序列循环，不会停） |
| 高频听力损失 | 主要音区 ≤2637Hz，不依赖 4kHz 以上成分 |
| 节奏感弱 | 所有单元时值一致（220/140ms），同一速度，无切分 |
| 完全无音乐训练 | "听见几声就是第几项，高八度=第 6 项起"两条口诀即可上手 |

产品化降低学习成本（Flutter 侧）：

1. **口诀文案**：调试页顶部原先的三条 `_InfoBanner`（摩擦轮激活与斜坡说明、提示音口诀、满油上限说明）已按用户要求全部删除，页面直接进入试听面板与测试项列表；试听面板自己的说明段与「标准/紧凑」开关也已删除，只留标题、一行「点一下听这一项的提示音（上行 N 声）」与逐项按钮。口诀现在靠按钮标签本身表达（「第 N 项 / 低·高音区 · 上行 N 声」）。
2. **逐项试听**：调试页「提示音试听」面板按当前启用项数列出按钮，标注「第 N 项 / 低·高音区 · 上行 N 声」，点一下听这一项的上行提示。—— **已实施**，见 `lib/src/debug_cue_preview.dart` 与 `_DebugCueAudition`。（原本还有「全部完成」按钮、风格开关与结束区回落，均已移除。）
3. **同源曲谱**：试听与固件共用 `DebugCues`（`packages/pieblock_core/lib/src/debug_cues.dart`）——固件把时值渲染成 `CUE_*` 宏、音高渲染成 `MotifNote()` 的 `switch`，UI 把同一条曲线合成方波 WAV 播放，听到的就是烧录后的效果，杜绝两边定义漂移。合成沿用项目已有的 `flutter_soloud`，**不引入新依赖，也不引入音频资源文件**。
4. **首次自动教学**：进入调试步骤时自动播放一遍全部事件音。—— **未做**，目前靠试听面板引导。

## 6. 实现要点（`_debug()` 生成器，已实施）

步序音高、时值都提为宏（时值取 `DebugCues` 的时值常量）；音型取音高用 `switch` 而不是"数组 + 变址"（SDCC 对该写法有已知取错字节的问题）。以下为生成出的实际代码（片段）：

```c
/* 音高：十二平均律，A4 = 440Hz */
#define CUE_C5 523
#define CUE_E5 659
#define CUE_G5 784
#define CUE_C6 1047
#define CUE_E6 1319
#define CUE_G6 1568
#define CUE_C7 2093
#define CUE_E7 2637
/* 上行音型长度（= 音区跨度 = 音数上限） */
#define CUE_MOTIF_LEN 5
/* 步序码：八度音区进位（项 1~5 低八度，项 6 起高八度） */
#define CUE_ZONE_SPAN 5
#define CUE_UNIT_MS 220
#define CUE_GAP_MS 140
/* 分区停顿：步序音与随后的测试动作之间的静默，
   必须明显长于 CUE_GAP_MS，否则动作噪音会盖掉步序音。 */
#define CUE_SECTION_GAP_MS 300
/* 项间与循环边界的静默：跑完最后一项后同样等这么久再回到第 1 项。 */
#define TEST_GAP_MS 1000

/* 上行音型第 index 个音（index 从 0 开始），high 为真时整体升八度。
   用 switch 而不是数组变址：SDCC 对 "数组 + 变址" 的写法有已知取错字节的
   问题（见 ExpansionBoradControl 里的注释），能避开就避开。 */
static uint16_t MotifNote(uint8_t index, uint8_t high)
{
    uint16_t octave = high ? 2 : 1;

    switch (index)
    {
    case 0: return (uint16_t)(CUE_C6 * octave);
    case 1: return (uint16_t)(CUE_E6 * octave);
    case 2: return (uint16_t)(CUE_G6 * octave);
    case 3: return (uint16_t)(CUE_C7 * octave);
    default: return (uint16_t)(CUE_E7 * octave);
    }
}

/* 步序提示：用上行音型的前 count 个音表示第 count 项——**个数即序号**。
   没有前奏，也没有结束区的回落。 */
static void StepCue(uint8_t step)
{
    /* 略：按 zone/count 逐音 Beep，音之间 Ms_Delay(CUE_GAP_MS) */
}
```

主循环（生成器模板，测试项命令由生成期按 `tests` 顺序展开）：

```c
void main(void)
{
    Board_Init();
    UART_Init(UART_1, UART1_RX_P30, UART1_TX_P31, 230400, TIM1);
    PWM_Init(BUZZER_CH, BUZZER_IDLE_FREQ, 0);

    /* 整段测试序列循环执行：跑完最后一项自动回到第 1 项。 */
    while (1)
    {
        /* 每轮开头先把两组 PWM 复位到 main 起始的 50Hz。逐项那条 Init 是
           生成期按「上一项之后」的静态状态决定要不要发的，只有每轮都从
           同一个状态起步，这条静态判断在第二轮及以后才继续成立。 */
        ExpansionBoradControl(Init_Order, 50, 50, 50, 50, 50, 50, 50, 50);
        Ms_Delay(20);

        /* 1. P64 friction */
        StepCue(1);
        Ms_Delay(CUE_SECTION_GAP_MS);
        Ms_Delay(1000);
        FrictionActivate(2);
        FrictionRampTo(2, 800);
        Ms_Delay(FRICTION_STEP_MS);
        FrictionRampTo(2, 0);
        Ms_Delay(TEST_GAP_MS);
        /* … 其余测试项同构 … */

        /* 一轮结束：八路输出全部归零，随后回到第 1 项。 */
        ExpansionBoradControl(Duty_Change_Order, 0, 0, 0, 0, 0, 0, 0, 0);
    }
}
```

宏值不写死在模板里，而是由 `DebugCues` 的时值常量（`unitMs` / `gapMs` / `sectionGapMs`）渲染；音型规则定义在 `DebugCues.ascent()`。

生成器替换点（均已实施）：

- `Beep(BUZZER_FREQ_READY, 200); Ms_Delay(200);` → `StepCue(${index + 1});`
- `Beep(BUZZER_FREQ_DONE, 200);` → 先变成 `Ms_Delay(CUE_SECTION_GAP_MS); DoneCue(${index + 1});`，**本轮连同 `DoneCue()` 一起删除**，只留动作前的那处 `Ms_Delay(CUE_SECTION_GAP_MS);`
- 原先 `while (1) { Beep(BUZZER_FREQ_DONE, 500); Ms_Delay(2000); }` → 先改成 `while (1) { AllDoneCue(); Ms_Delay(CUE_ALLDONE_REPEAT_MS); }`（序列只跑一次、随后循环播《卡农》），**再改为整段序列放在 `while (1)` 里循环**，跑完最后一项回到第 1 项。
- `BUZZER_FREQ_READY` / `BUZZER_FREQ_DONE` 已删除，收敛为 `BUZZER_IDLE_FREQ`（仅作静音占位，配合占空比 0 使用）；`FrictionActivate()`、`FrictionRampTo()`、`PWM_Init()` 三处静音调用同步改名。
- `Beep()` 内的发声占空比由字面量 `5000` 提为 `BUZZER_DUTY_ON`。
- 时值由字面量提为 `CUE_*` 宏（回落专用的 `CUE_EVENT_DONE_MS` / `CUE_EVENT_GAP_MS` 已随回落删除）。
- 开始区删除时一并清掉了只服务于它的 `ReadyCue()` 函数、`CUE_EVENT_NOTE_MS` 宏，以及 `DebugCues.ready()` / `done()` 与当时 `eventTiming()` 记录里的 `eventNoteMs` 字段——不留没人用的宏和曲线。
- 时值统一收敛到 `DebugCues` 的 `unitMs` / `gapMs` / `sectionGapMs` 常量，固件与试听共用同一套数值，不再手写第二套。
- 旧版的 `CUE_ZONE_LOW` / `CUE_ZONE_HIGH` 两个宏已删除（音区由 `MotifNote` 的 `octave` 参数承担）。

## 7. 备选方案与取舍

| 方案 | 机制 | 区分度 | 学习成本 | 实现量 |
| --- | --- | --- | --- | --- |
| A 纯计数（BIOS 哨音码） | N 声同音高短音 | 中（≤5 步可用，之后崩溃） | 低 | 极小 |
| B 本方案（上行音型 + 个数 + 音区进位） | 音型前缀即序号，只有一段上行 | 高 | 低 | 小 |
| C 逐步独立旋律（Marlin 风格） | 每步一段 3–6 音 motif | 最高 | 高（需背 10 段） | 大（曲谱表） |
| D 音阶取音（每步一个音级） | 每步换音高，如 do-re-mi… | 中高 | 中（需辨音级） | 小 |

已实施 B。B 相对 D 的优势是**个数自校验**：听到 N 声就知道是第 N 项，不必判断是哪个音；相对 A 的优势是超过 5 步不会崩溃（八度进位），而且每项只占不到 2 秒。

> 曾经多一层"开始区（完整音型前奏）"，已按用户意见删除：既然个数已经说明序号，前奏就是重复信息。
>
> 曾经有一层"结束区"（同一音型跳过落音后倒序的回落乐句），也按用户意见删除：它不携带新信息，却比整段上行还长（见 3.2）。
>
> 也曾经用《卡农》全曲做"全部完成"收尾旋律（多声部归并为单音线、854 音、约 5 分钟），随序列改为循环执行一并删除：循环里没有"全部完成"这个终态。

若战队愿意投入培训成本，C 可作为"进阶皮肤"：`StepCue` 改为查 `static const Note stepSongs[10][]` 表即可——与项目已有的 MIDI 音乐生成器（`_music()`，128 音等程频率表、`MusicSegment` 结构）完全同构，Flutter 端同一套曲谱可直接用于试听页，复用成本低。
