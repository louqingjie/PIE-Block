# 调试模式蜂鸣器提示音方案

> 状态：**已实施**（提交 `7e19761`），本文档与代码实况一致
> 相关代码：`packages/pieblock_core/lib/src/code_generator.dart` 的 `_debug()`（约 980–1240 行）

## 1. 现状与问题

调试工程按 `tests` 顺序逐项执行（每个启用的引脚一个测试项，默认 3s，项间间隔 1s，最多 10 项）。当前提示音：

| 时机 | 当前实现 | 听感 |
| --- | --- | --- |
| 每个测试项开始 | `Beep(500, 200)` | 平音一声 |
| 每个测试项结束 | `Beep(700, 200)` | 平音一声 |
| 摩擦轮激活 1000ms | 静音（PWM duty=0） | — |
| 摩擦轮斜坡 | 蜂鸣频率 = 当前占空比 | 上行扫频（连续量） |
| 全部完成 | `Beep(700, 500)` 每 2s 循环 | 平音一声 |

问题：

1. **步序无编码**。每个测试项的开始音、结束音完全相同，用户只能靠数"嘀"推断进度；一旦走神即错，且无法区分"第 2 步开始"与"第 5 步结束"。
2. **轮廓缺失**。500Hz 与 700Hz 均为平音，仅差 200Hz；而无源压电蜂鸣器在 ~500Hz 附近响应弱、音量小，赛场噪声下更难分辨。
3. **事件类型少且听感接近**。"开始 / 结束 / 全部完成"三类中，后两类都是短平音，缺少身份感。

## 2. 硬件可控维度

蜂鸣器为 P33 无源蜂鸣器，由 `PWM_SET_Frequency(BUZZER_CH, freq, 5000)` 驱动：

- 可控：**音高**（频率）、**节奏**（通断时值）、**旋律轮廓**（音高升降走向）。
- 不可控：音量、音色（单音方波）。

因此区分度设计只能围绕"音高 × 节奏 × 轮廓"展开，不追求音色变化。

## 3. 推荐方案：三通道编码

总原则：**轮廓编码事件，音区 + 点数编码步序，扫频编码过程量**。三个通道各管一层、互不混淆。

### 3.1 事件语法（轮廓编码）

每个事件配一个固定小旋律，**升降轮廓即语义**——这是对音高记忆依赖最小的感知通道，音高感弱的人也能听出"往上"还是"往下"。

| 事件 | 旋律（十二平均律，A4=440Hz） | 轮廓 | 时长 |
| --- | --- | --- | --- |
| READY 步骤开始 | C6(1047) → E6(1319) → G6(1568)，90ms/音，间隔 40ms | 上行大三分解 | ~350ms |
| DONE 步骤完成 | G6(1568) → C6(1047)，140ms/音，间隔 50ms | 下行四度 | ~330ms |
| ALL-DONE 全部完成 | C5(523) → E5(659) → G5(784) → C6(1047)，前三音 120ms、尾音 300ms，每 2s 循环 | 长上行琶音 | ~700ms |
| （可选）注意 | 500Hz 短音 ×3 | 平音重复 | ~400ms |

依据：

- READY 上行 = "起"，DONE 下行 = "落"。只听方向即可判断当前在测试前还是测试后，不需要记住音高。
- ALL-DONE 是**唯一从低音区（523Hz）起音**的旋律，且最长、带循环，与步骤音形成"音区 + 长度"双重隔离。它与步兵/工程启动曲（523-659-784-1047）同曲，老用户有连续性。
- 三个事件音全部落在 523–1568Hz，处于无源压电蜂鸣器较好响应区（现有 500Hz 在弱区）。

### 3.2 步序编码（音区 + 点数，双通道）

设步序 N 从 1 开始：

- **点数通道**：`count = (N - 1) % 5 + 1` 声短音，110ms 响 / 70ms 空。
- **音区通道**：`zone = (N - 1) / 5` → 低音区 G5=784Hz / 高音区 G6=1568Hz（**八度**，普通人最易分辨的音程）。

| 步序 | 音区 | 点数 | 听感 |
| --- | --- | --- | --- |
| 1 | 低 784 | 1 | 嗒 |
| 2 | 低 784 | 2 | 嗒 嗒 |
| 3 | 低 784 | 3 | 嗒 嗒 嗒 |
| 4 | 低 784 | 4 | 嗒 ×4 |
| 5 | 低 784 | 5 | 嗒 ×5（密集五连） |
| 6 | 高 1568 | 1 | 叮（八度跃升，一听即知进位） |
| 7 | 高 1568 | 2 | 叮 叮 |
| 8 | 高 1568 | 3 | 叮 ×3 |
| 9 | 高 1568 | 4 | 叮 ×4 |
| 10 | 高 1568 | 5 | 叮 ×5 |

设计依据：

- **点数上限 5**：人类可靠计数约 4–5（subitizing + 瞬时计数）。超过 5 用八度音区"进一位"，即电话区号式编码；若将来超过 10 步，再加一个音区（如 2093Hz）即可扩展到 15 步。
- **八度做音区间隔**：半音/全音阶梯对未受训练者区分度差，且蜂鸣器频率随温度与 PWM 粒度存在偏差；八度间隔大、鲁棒。
- **双通道冗余**：数不准 → 听音区估区间；听不准音区 → 数点数。两类弱项不会同时发生，互为保险。
- **框架一致**：所有提示同一速度、同一占空比（音色一致），耳朵只需学"一套语法"，学习成本低。

### 3.3 过程量编码（保留摩擦轮扫频）

摩擦轮斜坡期间蜂鸣频率 = 当前占空比（现有行为），编码的是**连续油门量**而非事件，与离散的步序/事件音不在同一时间平面，不冲突，保留。激活期 1000ms 静音也保留——它本身即可作为"即将扫频"的可辨识信号。

### 3.4 视觉冗余（本次未做，有明确理由）

共享运行时的 `LedShow()` 只有 3 位（P3^5/6/7），可表示 0–7，而调试序列最多 10 项——步 8/9/10 会回绕成 0/1/2，**恰好在最需要区分的区间引入歧义**，因此本次不纳入。若日后要做，应先增加显示位数（如改用 4 位或双位闪烁），而不是直接复用 `LedShow(step & 0x07)`。

替代方案是把辨识负担放在文案上：wizard 调试页已新增一条说明 banner，用自然语言给出「上升=开始、下降=结束；几声=第几项；高八度=第 6 项起」的口诀。

## 4. 单步听觉时间线

```
[READY 350ms] [步序码 ≤830ms] [测试执行 durationMs（默认 3000ms）] [DONE 330ms] [项间间隔 1000ms]
```

提示音开销：第 1 步约 860ms，第 5/10 步约 1.5s。相对默认 3s 测试可接受；但用户若把 `durationMs` 调得很短（如 500ms），提示音会喧宾夺主。建议 wizard 暴露**提示音风格**（标准 / 紧凑），或至少把时值集中为 `#define` 便于统一调整：

- 标准：110/70ms 单元，事件音如 3.1 表；
- 紧凑：60/30ms 单元，事件音压缩为两音（READY 1047→1568，DONE 1568→1047），最坏开销降到约 810ms。

## 5. 不同辨识难度的兼顾

| 用户弱项 | 本方案的兜底 |
| --- | --- |
| 音高记忆弱 / 四音不全（约 4% 人群） | 轮廓（升降）+ 点数计数不依赖音高记忆；音区只要求分辨八度 |
| 计数弱 / 容易走神 | 点数 ≤5；音区给出粗区间；错过可等下一个 READY 重新同步 |
| 高频听力损失 | 主要音区 ≤1568Hz，不依赖 4kHz 以上成分 |
| 节奏感弱 | 所有单元时值一致（110/70ms），同一速度，无切分 |
| 完全无音乐训练 | "上升=开始，下降=结束，几声=第几步，高八度=第 6 步起"三条口诀即可上手 |

产品化降低学习成本（Flutter 侧）：

1. **口诀文案**：wizard 说明区写入口诀（见上表最后一行）。—— **已实施**，调试页新增一条 `_InfoBanner`。
2. **试听与图例**：调试页加「提示音试听」面板，可逐条试听开始 / 结束 / 全部完成，以及每一项的完整提示（按当前启用项数列出步序按钮）。—— **已实施**，见 `lib/src/debug_cue_preview.dart` 与 `_DebugCueAudition`。
3. **同源曲谱**：试听与固件共用 `DebugCues`（`packages/pieblock_core/lib/src/debug_cues.dart`）——固件把时值渲染成 `CUE_*` 宏，UI 把同一条曲线合成方波 WAV 播放，听到的就是烧录后的效果，杜绝两边定义漂移。合成沿用项目已有的 `flutter_soloud`，**不引入新依赖，也不引入音频资源文件**。
4. **首次自动教学**：进入调试步骤时自动播放一遍全部事件音。—— **未做**，目前靠试听面板引导。

### 提示音风格（标准 / 紧凑）

`DebugConfig.cueStyle` 可选 `DebugCueStyle.standard`（默认）与 `compact`，用于 durationMs 很短的调试序列：

| 风格 | 步序单元/间隔 | READY 音 | DONE 音 | 单项提示合计（步 1～10） |
| --- | --- | --- | --- | --- |
| 标准 | 110 / 70 ms | 90 ms | 140 ms | 0.78s ～ 1.50s |
| 紧凑 | 60 / 30 ms | 60 ms | 70 ms | 0.44s ～ 0.80s |

音高、音区、点数编码方式**不随风格变化**，因此切换风格不会影响辨识逻辑，只是把提示音压缩得更短。旧项目文件没有 `cue_style` 字段时回落到标准风格。

## 6. 实现要点（`_debug()` 生成器改动，已实施）

实际落地时把音高与时值都提为宏（时值随「提示音风格」配置渲染），`StepCue` 用三元表达式取音区而非局部数组（SDCC 对数组变址有已知告警，能避开就避开）。以下为**标准风格**生成出的实际代码：

```c
/* 音高：十二平均律，A4 = 440Hz */
#define CUE_C5 523
#define CUE_E5 659
#define CUE_G5 784
#define CUE_C6 1047
#define CUE_E6 1319
#define CUE_G6 1568
/* 步序码：八度音区 + 点数单元时值（时值随「提示音风格」配置渲染） */
#define CUE_ZONE_LOW CUE_G5
#define CUE_ZONE_HIGH CUE_G6
#define CUE_ZONE_SPAN 5
#define CUE_UNIT_MS 110
#define CUE_GAP_MS 70
/* 事件音时值 */
#define CUE_EVENT_NOTE_MS 90
#define CUE_EVENT_DONE_MS 140
#define CUE_EVENT_GAP_MS 40
#define CUE_ALLDONE_NOTE_MS 120
#define CUE_ALLDONE_TAIL_MS 300

/* 事件音：固定旋律语法 */
static void ReadyCue(void)
{
    Beep(CUE_C6, CUE_EVENT_NOTE_MS); Ms_Delay(CUE_EVENT_GAP_MS);
    Beep(CUE_E6, CUE_EVENT_NOTE_MS); Ms_Delay(CUE_EVENT_GAP_MS);
    Beep(CUE_G6, CUE_EVENT_NOTE_MS);
}

static void DoneCue(void)
{
    Beep(CUE_G6, CUE_EVENT_DONE_MS); Ms_Delay(CUE_EVENT_GAP_MS);
    Beep(CUE_C6, CUE_EVENT_DONE_MS);
}

/* 步序音：音区（八度）+ 点数（<=5） */
static void StepCue(uint8_t step) /* step 从 1 开始 */
{
    uint8_t zone = (uint8_t)((step - 1) / CUE_ZONE_SPAN);
    uint8_t count = (uint8_t)((step - 1) % CUE_ZONE_SPAN + 1);
    uint8_t i;
    for (i = 0; i < count; i++) {
        Beep(zone ? CUE_ZONE_HIGH : CUE_ZONE_LOW, CUE_UNIT_MS);
        if (i + 1 < count) Ms_Delay(CUE_GAP_MS);
    }
}

/* 全部完成：低音区起音的长琶音，每 2s 循环 */
static void AllDoneCue(void)
{
    Beep(CUE_C5, CUE_ALLDONE_NOTE_MS); Ms_Delay(CUE_EVENT_GAP_MS);
    Beep(CUE_E5, CUE_ALLDONE_NOTE_MS); Ms_Delay(CUE_EVENT_GAP_MS);
    Beep(CUE_G5, CUE_ALLDONE_NOTE_MS); Ms_Delay(CUE_EVENT_GAP_MS);
    Beep(CUE_C6, CUE_ALLDONE_TAIL_MS);
}
```

宏值不写死在模板里，而是由 `DebugCues.stepTiming()` / `DebugCues.eventTiming()` 按 `DebugConfig.cueStyle` 渲染——同一份数据也供 UI 试听使用。

生成器替换点（均已实施）：

- `Beep(BUZZER_FREQ_READY, 200); Ms_Delay(200);` → `ReadyCue(); StepCue(${index + 1});`
- `Beep(BUZZER_FREQ_DONE, 200);` → `DoneCue();`
- `while (1) { Beep(BUZZER_FREQ_DONE, 500); Ms_Delay(2000); }` → `while (1) { AllDoneCue(); Ms_Delay(2000); }`
- `BUZZER_FREQ_READY` / `BUZZER_FREQ_DONE` 已删除，收敛为 `BUZZER_IDLE_FREQ`（仅作静音占位，配合占空比 0 使用）；`FrictionActivate()`、`FrictionRampTo()`、`PWM_Init()` 三处静音调用同步改名。
- `Beep()` 内的发声占空比由字面量 `5000` 提为 `BUZZER_DUTY_ON`。
- 事件音时值由字面量提为 `CUE_EVENT_*` / `CUE_ALLDONE_*` 宏，紧凑风格才能真正压缩。
- 未采纳 3.4 的 LED 显示（理由见该节）。

同步事项（均已完成）：

- `pieblock_core_test.dart` 中断言 `BUZZER_FREQ_READY` 的用例改为 `BUZZER_IDLE_FREQ`；新增「调试提示音用事件轮廓与步序双通道区分」「紧凑提示音风格压缩全部时值宏」「提示音风格随项目文件往返且旧文件回落标准」「提示音曲谱的步序映射符合音区与点数双通道」四项覆盖。

## 7. 备选方案与取舍

| 方案 | 机制 | 区分度 | 学习成本 | 实现量 |
| --- | --- | --- | --- | --- |
| A 纯计数（BIOS 哨音码） | N 声同音高短音 | 中（≤5 步可用，之后崩溃） | 低 | 极小 |
| B 本方案（音区 + 点数 + 事件语法） | 双通道冗余 + 轮廓 | 高 | 低 | 小 |
| C 逐步独立旋律（Marlin 风格） | 每步一段 3–6 音 motif | 最高 | 高（需背 10 段） | 大（曲谱表） |

已实施 B。若战队愿意投入培训成本，C 可作为"进阶皮肤"：`StepCue` 改为查 `static const Note stepSongs[10][]` 表即可——与项目已有的 MIDI 音乐生成器（`_music()`，128 音等程频率表、`MusicSegment` 结构）完全同构，Flutter 端同一套曲谱可直接用于试听页，复用成本低。
