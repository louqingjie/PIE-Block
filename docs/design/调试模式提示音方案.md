# 调试模式蜂鸣器提示音方案

> 状态：**已实施**，本文档与代码实况一致
> 相关代码：`packages/pieblock_core/lib/src/code_generator.dart` 的 `_debug()`（约 940–1320 行）、曲谱 `packages/pieblock_core/lib/src/debug_cues.dart`

## 1. 现状与问题

调试工程按 `tests` 顺序逐项执行（每个启用的引脚一个测试项，默认 3s，项间间隔 1s，最多 10 项）。改造前提示音：

| 时机 | 旧实现 | 听感 |
| --- | --- | --- |
| 每个测试项开始 | `Beep(500, 200)` | 平音一声 |
| 每个测试项结束 | `Beep(700, 200)` | 平音一声 |
| 摩擦轮激活 1000ms | 静音（PWM duty=0） | — |
| 摩擦轮斜坡 | 蜂鸣频率 = 当前占空比 | 上行扫频（连续量） |
| 全部完成 | `Beep(700, 500)` 每 2s 循环 | 平音一声 |

问题：

1. **步序无编码**。每个测试项的开始音、结束音完全相同，用户只能靠数"嘀"推断进度；一旦走神即错，且无法区分"第 2 步开始"与"第 5 步结束"。
2. **轮廓缺失**。500Hz 与 700Hz 均为平音，仅差 200Hz；而无源压电蜂鸣器在 ~500Hz 附近响应弱、音量小，赛场噪声下更难分辨。
3. **事件类型少且听感接近**。"开始 / 结束 / 全部完成"三类中，后两类都是短平音，缺少身份感。

## 2. 硬件可控维度

蜂鸣器为 P33 无源蜂鸣器，由 `PWM_SET_Frequency(BUZZER_CH, freq, 5000)` 驱动：

- 可控：**音高**（频率）、**节奏**（通断时值）、**旋律轮廓**（音高升降走向）。
- 不可控：音量、音色（单音方波）。

因此区分度设计只能围绕"音高 × 节奏 × 轮廓"展开，不追求音色变化。

## 3. 方案：一条上行音型贯穿全局

**总原则：不要为不同层各造一套声音，而让步序与结束共用同一句旋律的一去一回。**

上行音型取 C6-E6-G6-C7-E7（十二平均律，A4=440Hz；前三音是原本的大三和弦分解，后两音按同一三度叠置续上，凑足 5 个音）：

| 层 | 取用方式 | 轮廓 |
| --- | --- | --- |
| 步序区（第 N 项） | **音型的前 N 个音**，220ms/音、间隔 140ms | 上行 N 音（个数即序号） |
| 结束区（DONE） | **同一音型跳过步序落音后倒序**，280ms/音、间隔 80ms | 回落 |
| 全部完成 | **《卡农》主题（MIDI 第一音轨）全曲**，408 音、约 3 分钟、每 2s 循环 | 完整乐句 |

听感上每项就是一句完整的乐句：**「上行 N 音 → 停 → 对称回落」**。

这解决了旧版"反复滴滴声与上行音乐不协调、显得突兀"的问题——步序不再是插进来的滴滴声，而是音型的自然截取；结束也不再是另一套声音，而是同一句旋律的回头。

> **为什么没有「开始区」**：早期版本在步序之前还播一遍完整音型（C6-E6-G6-C7-E7）当作 READY 前奏，但**个数本身已经承载了序号信息**，再播一遍完整音型只是把同一句话说了两遍，还把每项提示凭空拉长 1 秒多（标准风格下 1.6s）。既然提示音是"听到几声就是第几项"，前奏就是纯冗余，已删除。连带删掉的还有它的时值宏 `CUE_EVENT_NOTE_MS`。

> **为什么全部完成用《卡农》而不是长琶音**：逐项提示是三条「上去、回来」的短乐句（最长 1820ms），如果全部完成也只是一句短琶音（1860ms），长度上几乎一样，只靠音区区分；而一段完整正曲（约 3 分钟）在**长度与复杂度**上都是完全不同的量级，一耳朵就能分辨，也不需要用户先学会"低音区 = 全部完成"这条规则。曲谱直接取 `FF14用——卡农.mid` 的第一音轨，逐音写进 `DebugCues._canonTheme`。

各层音高（标准风格）：

| 层 | 音高序列 |
| --- | --- |
| 音型（供截取，不单独播） | 1047 1319 1568 2093 2637 |
| 步序 第 3 项 | 1047 1319 1568 |
| 结束 第 3 项 | 1319 1047 |
| 步序 第 6 项（升八度） | 2094 |
| 结束 第 6 项 | 2094 |
| 全部完成（头部 12 音） | 330 392 523 294 392 494 262 330 440 247 330 392 … |

### 3.1 音区（八度）负责进位

`zone = (N - 1) / 5` → 项 1~5 用低八度那组（1047 起），项 6~10 用高八度那组（2094 起）。八度是普通人最易分辨的音程，也是半音/全音阶梯最鲁棒的选择（蜂鸣器频率随温度与 PWM 粒度有偏差）。

| 步序 | 音区 | 上行音数 | 听感 |
| --- | --- | --- | --- |
| 1 | 低 | 1 | 哆 |
| 2 | 低 | 2 | 哆 咪 |
| 3 | 低 | 3 | 哆 咪 嗦 |
| 4 | 低 | 4 | 哆 咪 嗦 哆′ |
| 5 | 低 | 5 | 哆 咪 嗦 哆′ 咪′ |
| 6 | 高 | 1 | 哆′（八度跃升，一听即知进位） |
| 7 | 高 | 2 | …… |
| 10 | 高 | 5 | 高八度完整音型 |

**音数上限 5**：人类可靠计数约 4–5（subitizing + 瞬时计数）。超过 5 用八度"进一位"，即电话区号式编码；若将来超过 10 步，再加一个音区（如 4186Hz）即可扩展到 15 步。

### 3.2 回落规则：跳过步序落音

回落**必须跳过步序落音本身**，即 `descent(count) = 音型前 count 个音去掉最后一个后倒序`：

| 项 | 步序音 | 回落音 | 说明 |
| --- | --- | --- | --- |
| 1 | `[1047]` | `[1047]` | 退化：跳过落音后为空，回到音型首音 |
| 2 | `[1047, 1319]` | `[1047]` | 单音回落，比落音低一个三度，方向明确 |
| 3 | `[1047, 1319, 1568]` | `[1319, 1047]` | — |
| 4 | `[1047, 1319, 1568, 2093]` | `[1568, 1319, 1047]` | — |
| 5 | `[1047, 1319, 1568, 2093, 2637]` | `[2093, 1568, 1319, 1047]` | 完整音型的回落 |

> **为什么是「跳过落音」而不是「去掉首音」**：若让回落取完整倒序（含落音），交界处就是「上行最高音 → 同一个最高音」两声同音高连读，用户分不出"步序结束"和"回落开始"。若机械地取「去掉首音后倒序」，第 2 项会得到 `[1319]`，而步序落音也是 1319，同样撞音高。正确规则是**从落音下面开始往回走**，即跳过落音、再倒序——这样只有第 1 项因为"落音下面没有音了"必须退化为单音。

由此得到一个额外的结构性质：**结束区永远不会比步序区更长**（项 1 等长，其余短 1 个音），听感上清清楚楚是"向上走、再退回来"。

### 3.3 交界处的退化项（已知取舍）

音型的**前两个音**（项 1 与项 6）在交界处无法拉开音高：

- 项 1：步序与回落都只剩音型首音，是同一个音；
- 项 6：步序是低音区的音型首音、回落是高音区的音型首音，八度刚好抵消，仍是同一个音。

这两项的序内辨识由**音区（八度）**承担——项 6 的整组声音比项 1 高一个八度，不需要靠交界处区分。项 3 起交界处天然有音高差（如第 3 项：落音 1568 → 回落起音 1319）。测试 `步序与回落之间不会同音高` / `结束区是步序音型的对称回落且不与步序落音撞音高` 对 `count > 2` 逐项断言，对退化区间只断言两端都真的发了声。

### 3.4 过程量编码（保留摩擦轮扫频）

摩擦轮斜坡期间蜂鸣频率 = 当前占空比（现有行为），编码的是**连续油门量**而非事件，与离散的步序/事件音不在同一时间平面，不冲突，保留。激活期 1000ms 静音也保留——它本身即可作为"即将扫频"的可辨识信号。

### 3.5 视觉冗余（本次未做，有明确理由）

共享运行时的 `LedShow()` 只有 3 位（P3^5/6/7），可表示 0–7，而调试序列最多 10 项——步 8/9/10 会回绕成 0/1/2，**恰好在最需要区分的区间引入歧义**，因此本次不纳入。若日后要做，应先增加显示位数（如改用 4 位或双位闪烁），而不是直接复用 `LedShow(step & 0x07)`。

替代方案是把辨识负担放在文案上：wizard 调试页已新增说明 banner，用自然语言给出「先上行几声、几声就是第几项、听到回落就是这一项结束」的口诀。

## 4. 单步听觉时间线

单步提示分成**两个听觉段落**，段与段之间用 300ms 静默（`CUE_SECTION_GAP_MS`）隔开：

```
[步序区 上行 N 音 ≤1.7s] ─停顿 300ms─ [测试执行 durationMs] ─停顿 300ms─ [结束区 回落 ≤1.1s] ─项间 1000ms─
```

停顿是必需的：步序音之间的内部间隔只有 140ms，只够把音符分开、听感上仍是**一个连续乐句**；300ms 以上才能让人听出"一段结束、另一段开始"。缺了它，"上行 N 音"和随后的回落会连成一片，用户分不出"这一项做完了"。同理，测试动作的噪音会盖掉步序音，所以动作前也要留停顿。

> 曲线的末尾不再有静默：删除开始区之后，回落就是整项提示的最后一段，`fullStep()` 因此以末音收尾。

提示音开销：第 1 步约 0.9s，第 5/10 步约 3.1s（含两处 300ms 停顿）。删除开始区把每项提示压缩了约 1.6s（标准风格），此前"标准偏长"的抱怨已基本缓解；但仍保留**提示音风格**（标准 / 紧凑）开关，供 durationMs 很短的调试序列整体加速：

- 标准：220/140ms 单元、300ms 分区停顿，回落音 280ms；
- 紧凑：标准风格**整体减半**（110/70ms 单元、150ms 停顿），即快一倍的速度。

若嫌标准偏长，只需调小 `DebugCues` 的 `_*Std` 基准（如 `_unitStd` 220→180）或把 `_sectionGapStd` 一起收窄，两种风格会同步跟随。

## 5. 不同辨识难度的兼顾

| 用户弱项 | 本方案的兜底 |
| --- | --- |
| 音高记忆弱 / 四音不全（约 4% 人群） | 个数计数 + 升降轮廓不依赖音高记忆；音区只要求分辨八度 |
| 计数弱 / 容易走神 | 音数 ≤5；音区给出粗区间；错过可等下一项重新同步 |
| 高频听力损失 | 主要音区 ≤2637Hz，不依赖 4kHz 以上成分 |
| 节奏感弱 | 所有单元时值一致（220/140ms），同一速度，无切分 |
| 完全无音乐训练 | "几声就是第几项，回落就是这一项结束，高八度=第 6 项起"三条口诀即可上手 |

1. **口诀文案**：wizard 说明区写入口诀（见上表最后一行）。—— **已实施**，调试页新增一条 `_InfoBanner`。

### 提示音风格（标准 / 紧凑）

`DebugConfig.cueStyle` 可选 `DebugCueStyle.standard`（默认）与 `compact`，用于 durationMs 很短的调试序列：

| 风格 | 步序单元/间隔 | 分区停顿 | 回落音 | 全部完成循环 | 单项提示合计（步 1～10） |
| --- | --- | --- | --- | --- | --- |
| 标准 | 220 / 140 ms | 300 ms | 280 ms | 2 s | 0.9s ～ 3.1s |
| 紧凑 | 110 / 70 ms | 150 ms | 140 ms | 1 s | 0.5s ～ 1.6s |

**紧凑风格的每一个时值都由标准风格除以 2 得到**，不是另写一套数值：`DebugCueStyle.scale()` 负责换算，`DebugCues` 里只保留 `_*Std` 一组基准常量。改速度就改基准（或调整 `_speedDivisor`），两种风格自动同步，不会再出现某个时值漏改导致的关系漂移。测试 `紧凑风格的每个时值都是标准风格的一半` 会逐项断言这层关系，包括每条完整提示曲线（含《卡农》全部 747 段）的每个时值。

全部完成是**固定曲谱**，它的音高与时值直接写在 `DebugCues._canonTheme` 数据里，不参与上面的基准常量体系——但**时值同样经 `scale()` 折算**，所以紧凑风格下正曲会整体快一倍（标准 180.9s / 紧凑 90.4s）。《卡农》曲谱的两遍循环间隔仍是 `CUE_ALLDONE_REPEAT_MS`（标准 2s / 紧凑 1s）——相对于两分钟的正曲，这个间隔只在曲末起分隔作用。

音高、音区、音数编码方式**不随风格变化**，因此切换风格不会影响辨识逻辑，只是把提示音整体加速一倍。旧项目文件没有 `cue_style` 字段时回落到标准风格。

## 6. 实现要点（`_debug()` 生成器改动，已实施）

步序与回落音高、时值都提为宏（时值随「提示音风格」配置渲染）；音型取音高用 `switch` 而不是"数组 + 变址"（SDCC 对该写法有已知取错字节的问题）。**全部完成是《卡农》曲谱，408 个音逐音字面量展开在 `AllDoneCue()` 里**——曲谱是固定数据，展开比宏更清楚，也天然避开数组变址问题。以下为**标准风格**生成出的实际代码（片段）：

```c
/* 音高：十二平均律，A4 = 440Hz */
#define CUE_C5 523
#define CUE_E5 659
#define CUE_G5 784
#define CUE_C6 1047
#define CUE_E6 1319
#define CUE_G6 1568
#define CUE_C7 2093
#define CUE_E7 2637
/* 上行音型长度（= 音区跨度 = 音数上限） */
#define CUE_MOTIF_LEN 5
/* 步序码：八度音区进位（项 1~5 低八度，项 6 起高八度） */
#define CUE_ZONE_SPAN 5
#define CUE_UNIT_MS 220
#define CUE_GAP_MS 140
/* 回落音时值 */
#define CUE_EVENT_DONE_MS 280
#define CUE_EVENT_GAP_MS 80
/* 分区停顿：步序音与测试动作、测试动作与回落之间的静默，
   必须明显长于 CUE_GAP_MS，否则去回两段会连成一个乐句，听不出边界。 */
#define CUE_SECTION_GAP_MS 300
#define CUE_ALLDONE_REPEAT_MS 2000

/* 上行音型第 index 个音（index 从 0 开始），high 为真时整体升八度。
   用 switch 而不是数组变址：SDCC 对 "数组 + 变址" 的写法有已知取错字节的
   问题（见 ExpansionBoradControl 里的注释），能避开就避开。 */
static uint16_t MotifNote(uint8_t index, uint8_t high)
{
    uint16_t octave = high ? 2 : 1;

    switch (index)
    {
    case 0: return (uint16_t)(CUE_C6 * octave);
    case 1: return (uint16_t)(CUE_E6 * octave);
    case 2: return (uint16_t)(CUE_G6 * octave);
    case 3: return (uint16_t)(CUE_C7 * octave);
    default: return (uint16_t)(CUE_E7 * octave);
    }
}

/* 步序提示：用上行音型的前 count 个音表示第 count 项——**个数即序号**，
   所以不需要先播一遍完整音型做前奏。音区（八度）负责进位。 */
static void StepCue(uint8_t step)
{
    uint8_t zone;
    uint8_t count;
    uint8_t i;

    zone = (uint8_t)((step - 1) / CUE_ZONE_SPAN);
    count = (uint8_t)((step - 1) % CUE_ZONE_SPAN + 1);
    for (i = 0; i < count; i++)
    {
        Beep(MotifNote(i, zone), CUE_UNIT_MS);
        if (i + 1 < count)
            Ms_Delay(CUE_GAP_MS);
    }
}

/* 步骤完成：步序音型的对称回落——从步序落音**下面**开始往回走。 */
static void DoneCue(uint8_t step)
{
    uint8_t zone;
    uint8_t count;
    uint8_t i;

    zone = (uint8_t)((step - 1) / CUE_ZONE_SPAN);
    count = (uint8_t)((step - 1) % CUE_ZONE_SPAN + 1);
    if (count == 1)
    {
        /* 项 1：跳过落音后为空，回到音型首音。 */
        Beep(MotifNote(0, zone), CUE_EVENT_DONE_MS);
        return;
    }
    for (i = (uint8_t)(count - 2); i > 0; i--)
    {
        Beep(MotifNote(i, zone), CUE_EVENT_DONE_MS);
        Ms_Delay(CUE_EVENT_GAP_MS);
    }
    Beep(MotifNote(0, zone), CUE_EVENT_DONE_MS);
}

/* 每项调用序列：去回两段之间用 CUE_SECTION_GAP_MS 分开 */
static void ExampleItem(void)
{
    StepCue(N);
    Ms_Delay(CUE_SECTION_GAP_MS);   /* 步序区 → 测试动作 */
    /* ... 测试动作 ... */
    Ms_Delay(CUE_SECTION_GAP_MS);   /* 测试动作 → 结束区 */
    DoneCue(N);
}

/* 全部完成：《卡农》主题（MIDI 第一音轨）全曲，408 音逐音展开，每 2s 循环。
   音高/时值逐音写死——曲谱是固定数据，展开比宏更清楚，
   也避开 SDCC 对「数组 + 变址」取错字节的问题。这里只截取首尾以示意： */
static void AllDoneCue(void)
{
    Beep(330, 100);  Ms_Delay(300);
    Beep(392, 100);  Ms_Delay(300);
    Beep(523, 100);  Ms_Delay(700);
    /* ... 中间 402 个音省略 ... */
```

### 《卡农》曲谱的已知取舍（用户明确选择「完全不改」）

原始 MIDI 第一音轨有 408 个音、约 54 小节、音域 MIDI 52~84，本次实施**不做任何裁剪、不调速度、不做音域适配**，因此存在三个物理层的已知代价：

1. **短音无法成调**：原始时值有 100 种（22ms~2821ms），其中 66 个音 ≤32ms。在无源蜂鸣器上，32ms 的 165Hz 低音只有约 5 个周期，听起来是「咔哒」而非音符。这些短音保留了原曲的断奏节奏型，故照原样保留。
2. **`Ms_Delay` 精度**：最小单位 1ms 且调用有循环开销，短音的实际时值会略长于标称值，整体节奏与原曲有微小漂移。
3. **代码体积**：`AllDoneCue()` 展开约 750 行，源文件由约 12KB 增至约 23KB。仍是固定数据的直接展开，可读性尚可，但不适合再往里塞第二段曲子。

## 7. 备选方案与取舍

| 方案 | 机制 | 区分度 | 学习成本 | 实现量 |
| --- | --- | --- | --- | --- |
| A 纯计数（BIOS 哨音码） | N 声同音高短音 | 中（≤5 步可用，之后崩溃） | 低 | 极小 |
| B 本方案（上行音型 + 个数 + 对称回落） | 同一句旋律的一去一回 | 高 | 低 | 小 |
| C 逐步独立旋律（Marlin 风格） | 每步一段 3–6 音 motif | 最高 | 高（需背 10 段） | 大（曲谱表） |
| D 音阶取音（每步一个音级） | 每步换音高，如 do-re-mi… | 中高 | 中（需辨音级） | 小 |

已实施 B。B 相对 D 的优势是**个数自校验**：听到 N 声就知道是第 N 项，不必判断是哪个音；且结束与步序同源，整段听下来是一句"上去、回来"的乐句而非两套声音。相对 A 的优势是超过 5 步不会崩溃（八度进位）。

> 曾经多一层"开始区（完整音型前奏）"，已按用户意见删除：既然个数已经说明序号，前奏就是重复信息。

若战队愿意投入培训成本，C 可作为"进阶皮肤"：`StepCue` 改为查 `static const Note stepSongs[10][]` 表即可——与项目已有的 MIDI 音乐生成器（`_music()`，128 音等程频率表、`MusicSegment` 结构）完全同构，Flutter 端同一套曲谱可直接用于试听页，复用成本低。
