# PIE-Block 交互手感评估与改进建议

评估日期：2026-10-17　评估对象：PIE-Block Flutter 桌面 / Web 应用（`lib/` 43 个 Dart 文件，含 `wizard_screen.dart` 4572 行、`music_editor.dart` 1440 行）

评估方式：**只读代码审查 + 真机截图目视**（`website/assets/shots/{wizard,review,code,music}.webp`）。本轮没有实跑应用、没有 profiling、没有无障碍树导出，因此凡涉及"实际卡顿量级 / 像素 / 触屏体感"的结论都单独标为**【推测】**，其余标为**【事实】**或**【已核验】**（由 Lead 亲自 read 原文复核过）。

## 0. 结论速览

**综合手感 6 / 10**（向导表单 6、钢琴卷帘 5、应用外壳 6）。

一句话诊断：**"长任务反馈"这一块做得接近专业水准，"即时反馈"和"键盘 / 指针语义"这两块几乎空白，另外有 3 处会让用户看到"和真实配置不一致的界面"。**

做得好的、建议保留的部分：

- 首页↔编辑页转场：220ms `easeOutCubic`、2.5% 位移、转场期 `IgnorePointer`、尊重系统"减少动态效果"（`lib/main.dart:119/142/220/207`）。
- 保存链路：500ms 防抖 + 常驻四态徽标（`lib/src/controller.dart:291-293`、`lib/src/wizard_screen.dart:963-995`）。
- 编译 / 烧录：进度条高度恒定不抖动、确定/不确定进度两种形态、可取消、失败文案可读（`wizard_screen.dart:4507-4511`、`4426-4433`）。
- 日志自动跟随"用户上滑即停、回底恢复、`jumpTo` 不打断"（`wizard_screen.dart:3921-3973`）——这是全仓库手感最专业的一段。
- 错误面板每条问题可点击跳回现场并高亮 1.4s（`wizard_screen.dart:1156-1174`、`133-152`）。
- 引脚冲突弹窗给出"占用并解除原分配 / 交换引脚"两个明确动作，而不是只说"冲突了"（`wizard_screen.dart:604-616`）。
- 模板工程加载失败**不静默降级**为空白项目（`lib/src/project_templates.dart:23-37`）。
- 音乐编辑器 Ctrl+Z/Y/C/V/Delete 覆盖全部数据修改入口（`music_editor.dart:67-76`、`859-868`）。

## 3. 三个走查剧本（"手感"到底差在哪）

### 剧本 A：一个用惯了 IDE 的同学第一次进来

预期：Tab 能走完表单；数字填完按回车能下沉到下一个字段或前进；`Ctrl+S` 有确认；`F5` 或某个键能编译；`Esc` 能退出聚焦/关弹窗。
实际（全部为代码事实）：`wizard_screen.dart` 全文没有 `onSubmitted` / `autofocus` / `Shortcuts`；`lib/` 全局只有音乐编辑器注册了 5 条快捷键；首页甚至没有初始焦点（`autofocus` 仅 2 处，都不在首页）。更糟的是，每个下拉外面套了一层**不可见、无反馈的 `Focus`**（`wizard_screen.dart:183-186`，29 处 `_FieldAnchor` 调用点中只有 2 处走 `focusHandledByChild`），Tab 到下拉时会先落在一个按回车没反应的节点上。
体感：**"这个软件好像只认鼠标"**。

### 剧本 B：想改一个轮子的 IO

预期：选一个新引脚 → 若冲突，弹窗问怎么处理 → 选"取消"就回到原样。
实际：`onChanged` 是 `async`，用户点选时 `DropdownButtonFormField` 内部已经 `didChange` 改了显示；弹窗返回 null 时（`wizard_screen.dart:592-594`）**不写模型**，于是字段停在配置里并不存在的引脚上，而且**不会自己回退**（见第 1 节修正）。用户继续往下点"下一步"时，还会被 `controller.dart:362-376` 送回**第一个出错步骤**，横幅只给一句"发现 N 项错误"和一个"知道了"按钮（`wizard_screen.dart:793-803`）。
体感：**"我明明改过了""它怎么又变了""我填的到底存没存"**——三连疑问，这是最容易让用户怀疑工具的一类反馈缺失。

### 剧本 C：用鼠标修一个 1/16 音符

预期：按住音符拖到目标位置；拖不准有吸附提示；拖到不允许的地方能看出来。
实际（三条都已复核原文）：
1. 抓音符中部拖动，左边界会被吸到指针上（`music_editor.dart:244-249` 用"指针绝对 tick"、`:276` 每帧把 `_dragOriginal` 换成新位置）→ 首次移动瞬跳约半个音符宽。
2. Resize 判定固定 10px（`:200`），而音符最小绘制宽度 8px（`:100-103`）；zoom 0.5 时 1/16 音符只有 15px 宽 → 几乎按哪儿都是"改时长"，移不动。
3. 没有拖动死区：框架对精确指针的 pan slop 是 2 逻辑像素，且 `_panStart` 无条件 `_undo.add(_config)`（`:201`）→ 点一下选中也可能改数据，而且第一次 Ctrl+Z "什么都没发生"（撤销的是未变化的快照）。
4. 全程没有悬停高亮、没有 grab / resize 光标（全仓库 `MouseRegion`=0）、没有滚轮缩放（只有一条 150px 滑杆，`:1105-1123`）、不能点时间轴定位播放头。
体感：**"每次下笔都要小心翼翼"**。

## 6. 根因与结构性建议

以上问题并非零散疏漏，背后有三个结构原因，建议在排期时一并处理，否则同类问题会继续长出来：

1. **`wizard_screen.dart` 4572 行单文件 + 字段组件各写一份**：`_NumberField` 与 `_DecimalNumberField` 各自复制了 FocusNode 绑定、解析、过滤逻辑，导致"非法输入清空值""隐形 Tab 停靠点"这类问题要改两遍。建议抽一层 `FieldKit`（受控 controller + clamp + `errorText`/`helperText` + Enter 前进 + FocusNode 生命周期），一处修好所有字段。
2. **全局可变状态没有归口**：`_fieldFocusNodes` / `_fieldAnchors` 是顶层 Map，`closeProject` 不清理，动态路径（模式、动作、测试项）会持续累积。建议改为按文档会话创建的容器，随 `closeProject`/`_adopt` 整体释放。
3. **交互逻辑与绘制、Widget 混写**：画布的命中判定、拖动、吸附、撤销都在 `State` 里，`TestGesture` 在全仓库测试中出现 **0** 次，所以这次的 P0 拖动问题不可能被现有测试拦住。建议把编辑交互抽成可单测的 `MusicEditorController`，并补拖拽/焦点/快捷键断言。

另外建议把"**无效操作必须反馈**"写成规范：禁用要解释（为什么点不了）、拒绝要可见（非法落点/重合/越界）、被撤销的操作要有痕迹（SnackBar + 撤销）。本项目在"长任务"上已经做到了，把同一标准搬到"即时交互"上，手感会立刻上一个台阶。
