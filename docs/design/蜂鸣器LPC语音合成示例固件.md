# 蜂鸣器 LPC 语音合成示例固件（BUZZER_VOICE_SMOKE）

## 结论先说

P33 无源蜂鸣器**可以**朗诵中文短句：本固件把「这是P六零，电机调试」和
「这是P六十，电机调试」两版语料合成为 10 阶 LPC 格型激励，用 8 位 PWM
占空比播出。约束候选集下的中文识别器对「六十」版给出约 **0.99** 的置信度命中，
听写也能听出「六…调试」；音质是对讲机/贺卡级别，不能当正常喇叭用。

对照：同一个识别器对**干净 TTS 参考音**做听写也只有 0.19 置信度且会写错字
（引擎是 2009 年前后的桌面听写模型），所以识别结论以**约束候选集**为主。

## 它和「蜂鸣器只会嘀嘀」的区别

| 做法 | 输出 | 能不能出人声 |
| --- | --- | --- |
| `Beep(freq, ms)` 单音方波 | 同一时刻只有一个频率 | 不能，只有语调没有音素 |
| 本固件：固定载波 + 逐样本改占空比 | 载波被压电片机械低通还原成音频包络 | 能，共振峰被保留 |

关键是把蜂鸣器**当扬声器**用：PWM 载波固定 129.6 kHz（`FOSC/256`，正好给出
8 位占空比分辨率），每个采样周期写一次比较值；50% 占空比等于无声。载波远高于
音频带，压电片自身的机械低通把占空比还原成音频包络——这正是音乐贺卡的原理。

## 链路

```
SAPI 中文 TTS（Microsoft Huihui，8kHz 单声道）
   └─ 重采样到 7.2kHz ─ 预加重 0.94 ─ 30ms 汉明窗 / 10ms 步长 ─ 自相关 ─ Levinson-Durbin
        ├─ k1..k10（反射系数）、残差 RMS（→ 增益）
        └─ 原始帧低通 900Hz → 归一化自相关 → 基音周期、周期性（→ 清浊混合比）
   └─ 8 位量化 → 参数帧表（13 字节/帧，100 帧/秒）→ voice_data.c
固件：Timer0 7.2kHz 中断
   └─ 激励（脉冲串 + 噪声混合）→ 10 阶格型全极点滤波 → 高频提升 → 8 位 PWM
```

参数帧格式（`VOICE_FRAME_BYTES = 3 + VOICE_ORDER = 13`）：

| 字节 | 含义 |
| --- | --- |
| 0 | 基音周期（样本数），0 = 无周期性激励 |
| 1 | 噪声混合比 0..255（0 = 纯脉冲串，255 = 纯噪声） |
| 2 | 增益 0..255，对 `8×残差RMS` 做开方压扩 |
| 3..12 | 反射系数 k1..k10，有符号 8 位，`q = round(127·k)` |

表里存的是 `q = -k`（Levinson 递推里的 `value`），合成时按 `q<<8` 解码成 Q15
（即 `k = q/128`）。每帧在 8 个子步上按 TMS5220 的 `0,1,2,3,4,5,6,8/8` 缓入表插值。

## 采样率与中断预算（这一版的主要工作）

第一版在 8 kHz、每样本约 25 次 **32 位乘法运行库调用**（`ecall __mullong`）：
单次约 466 周期（由实测反推），合计约 14 900 周期 ≈ **449 µs**，而 8 kHz 的
预算只有 125 µs——中断被持续追尾，实际采样率掉到约 2.2 kHz，**播放慢 3.6 倍**
（实机表现：P35 亮 12 s 才换灯，正是 3.34 s 的 3.6 倍）。

修完之后热路径里一次 32 位乘法都没有：

| 手段 | 效果 |
| --- | --- |
| 格型 Q15 乘法改成两条 `mul ab`（无符号 8×8 硬件乘） | SDCC 对 `uint8_t*uint8_t` 直接出 `mul ab`，对 `int8_t/int16_t` 一律调 `__mulint` |
| 系数只保留 8 位精度，按绝对值+符号拆算，**无分支** | 三元表达式会被编成一串 `ejmp`；改成位运算后大幅缩短 |
| 插值 `lerp` 只用一条 `mul ab` | `(d*w)>>8 = (d*w/2)>>7`，|d| ≤ 255 保证乘积装进 16 位 |
| 激励增益每子步预计算 | 样本级只剩两次 `mul ab` |
| 热状态放进近内存 `__data` | `--model-large` 下数组索引要先算 24 位地址（22 条指令），近内存是 `@Ri`（10 条） |
| 格型乘法宏内联 | 省掉每样本 20 次函数调用与现场保存 |
| 该工程单独用 `--opt-code-speed` | 清单里可为项目覆盖 `compile_flags` |
| 采样率 8 kHz → 7.2 kHz | 预算 125 → 139 µs；带宽只掉 10%（10 阶在 8 kHz 下要 130 µs，正好顶穿） |

`check_voice_model.py` 会扫 `voice_synth.asm`：热路径里出现 32 位乘除运行库调用
直接失败，并按指令估算每样本周期数（预算 = 1/采样率），当前 **129.7 µs / 138.9 µs
= 93%**。估算的单指令周期按实测校准过（上一版 449 µs 反推约 466 周期/次
`__mullong`），所以不是拍脑袋的余量。

## 定点设计要点

* **格型更新顺序**：分析格型是
  `f_m(n) = f_{m-1}(n) + k_m·b_{m-1}(n-1)`、
  `b_m(n) = b_{m-1}(n-1) + k_m·f_{m-1}(n)`（b 用的是**本级的输入**）。
  反解时必须**先用旧状态算出新的 f_{m-1}，再用新的 f_{m-1} 更新 b_m**。
  顺序写反会得到一个完全不同的滤波器：内部状态发散到 int16 溢出，而输出听上去
  只是"有点怪"，很难靠听感发现。
* **余量**：格型内部的后向误差状态可达激励幅度的约 30 倍（高 Q 共振帧的 L1
  增益）。因此激励进格型前右移 4 位（`VOICE_EXC_SHIFT`），输出相应右移
  `8-4=4` 位取高 8 位送 PWM，两者相加必须为 8。
* **周期插值**：清浊切换处不插值周期。否则会在 10 ms 内扫过几十 Hz～几百 Hz
  的假基音，听感是"咔"一声。
* **电平校准**：整体增益系数由 `make_voice_params.py` 二分搜索——
  约束是"8 位输出不削顶"且"格型内部不越界"，两个约束对增益都单调。
  校准量直接吸收进生成的 `voiceGainTable`，固件侧没有额外常数。
* **基音检测不能用预加重残差**：0.94 的预加重会把声门脉冲能量摊开，
  归一化自相关峰被压到 0.3 左右，导致大量浊音帧被误判成噪声。
  改为在**原始帧低通 900 Hz** 后求自相关，并让周期性 ≥0.45 的帧取纯脉冲激励。

## 验证证据

`build_voice.ps1` 每次都会跑完下面几项，全部通过才继续构建：

| 检查 | 判据 | 结果 |
| --- | --- | --- |
| `mul_q8` / `lerp_q8` 精确性 | 与 32 位写法**完全相等**（边界 + 20 万组随机） | 通过 |
| 2 阶闭式校验 | `k=[0.3,-0.4]` 时 `y[1] = -a1·100 = -17.86` | 格型给 -19（定点取整） |
| 格型 ↔ 直接型 | 20 组随机反射系数的波形相关性 | 最低 0.9997 |
| 参数表电平 | 8 位输出峰值 < 128 且无削顶样本 | 108/128，0.00% 削顶 |
| **C ↔ Python 逐样本** | `voice_synth.c` 编成原生程序与定点模型比对 | 18360 样本，**0 处不同** |
| **C 的 MulQ8/Lerp** | 与 Python 穷举比对边界取值 | 7025 组，0 处不同 |
| **中断预算** | 热路径无 32 位乘除库调用；估算周期 ≤ 预算 | 93% |

第五、六项是最强的两条：`gcc -DVOICE_CODE= -DVOICE_NEAR= -DVOICE_HOST_BUILD`
把固件里的合成器编成主机程序，与 `voice_model.py`（同一份定点规格）逐样本比对，
判据是**完全相等**。

中文识别（`recognize_wav.ps1`，16 kHz 输入）：

| 音频 | 语法 | 结果 | 置信度 |
| --- | --- | --- | --- |
| 干净 TTS 参考音（六零） | 候选集 | 这是P六零电机调试 | 0.990 |
| 干净 TTS 参考音（六十） | 候选集 | 这是P六十电机调试 | 0.991 |
| 合成音 PLiushi | 候选集（仅六十） | **这是P六十电机调试** | **0.989** |
| 合成音 PLiuling | 候选集（仅六零） | 未命中 | — |
| 合成音 PLiuling | 听写 | 六连IP调试 | 0.064 |
| 合成音 PLiushi | 听写 | 六是IP调试 | 0.102 |

「六零」版在约束语法下未被命中（引擎整段拒绝），但听写能听出「六…调试」；
两版语料只差一个音节，这个差异更像是识别器的拒识阈值而非合成质量。
识别器前端按 16 kHz 处理，喂低采样率会得到完全错误的结果，所以
`make_voice_params.py` 会额外输出 `*_16k.wav`。

## 复现

```powershell
# 一条命令：TTS 参考音 -> 重采样 -> LPC 参数表 -> 定点校验 -> SDCC 固件 -> 中断预算
pwsh .\stc32g_sdcc\build_voice.ps1 `
  -Python <带 numpy 的 python> `
  -Sdcc .\vendor\sdcc-toolchain\bin\sdcc.exe `
  -LibDir .\vendor\sdcc-toolchain\lib\mcs251-large-stack-auto `
  -StdInclude .\vendor\sdcc-toolchain\include
# 产物：stc32g_sdcc\build\BUZZER_VOICE_SMOKE\BUZZER_VOICE_SMOKE.hex
# 试听：output\试听\voice\{PLiuling,PLiushi}_{synth,16k,piezo}.wav
```

`*_synth.wav` 是**固件定点算法的逐样本预测**（不含压电片频响），
`*_piezo.wav` 额外套了一层压电片频响的粗略模拟（600 Hz 一阶高通 + 2.9 kHz
谐振峰），更接近真机听感。

## 响度（实机偏轻的原因与对策）

压电片只在谐振带（约 2–4 kHz）效率高，而语音能量集中在 500 Hz–1 kHz；加上单端
驱动电压受限、语音本身峰值因子高（8 位输出的 RMS 只有峰值的 1/13），实机听感偏轻。

软件侧做了三件事。判据用**压电域 RMS**——把合成音过一遍压电片频响模型后的 RMS，
比 8 位 RMS 更接近真机听感：

| 手段 | 压电域 RMS | 说明 |
| --- | --- | --- |
| 基线（峰值 84%、无压缩） | 3312 | |
| 峰值提到 96% + 载波 129.6 → 64.8 kHz | — | 载波降一半让压电片容抗翻倍、分压损失减小 |
| 再加 压缩 γ=0.85 / 帧压缩 γ=0.85 | 4797（+3.2 dB） | 温和档，波形失真小 |
| 再加 压缩 γ=0.7 / 帧压缩 γ=0.75 | **5821（+4.9 dB）** | **当前默认**；8 位 RMS 10.4 → 20.1，仍 0% 削顶 |
| 再往下 0.6/0.65、0.5/0.55 | 6170 / 6826 | 每档只多约 0.5 dB，失真明显上升，收益饱和 |

压缩强度写在 `voice.json` 的 `compression_gamma` / `gain_compression_gamma`，
改完重跑 `build_voice.ps1` 即可；校准会重新把峰值压到 96%，所以任何档位都不会削顶。
**注意**：识别器对压缩本身敏感——把同一套压缩加到**干净 TTS 参考音**上也会从 0.991
掉到整段拒识，所以它不能用来判断压缩对人耳可懂度的影响；压缩档位请以真机听感为准。

线性手段（把能量搬到 2–4 kHz 的加强倾角）实测在压电域几乎无益甚至更小
（a=1/2 时 3404、a=3/4 时 3198，均不如基线）：切掉低频损失的能量大于高频抬升的收益。

想再明显变响只能动硬件：驱动级换 5 V/12 V、或加三极管/桥接驱动（+6~20 dB），
或外接小喇叭 + 功放（数量级差距）。

## 实机频响实测（用户录音分析）

用户按扫频段录音（两个文件都是扫频，12 段各 0.31s、间隔 0.45s，与固件一致）。
用 ffmpeg 解码后按段量**基频带**幅度（dB 相对 4.5 kHz）：

| 频率 | 基频响应 | 频率 | 基频响应 |
| --- | --- | --- | --- |
| 500 Hz | −48.5 dB | 2.4 kHz | −4.7 dB |
| 700 Hz | −38.1 dB | 2.8 kHz | −2.0 dB |
| 1.0 kHz | −34.5 dB | 3.2 kHz | −1.0 dB |
| 1.3 kHz | −36.6 dB | 3.6 kHz | −0.2 dB |
| 1.6 kHz | −26.5 dB | 4.0 kHz | −0.1 dB |
| 2.0 kHz | −10.2 dB | 4.5 kHz | 0.0 dB |

要点：

* **基频响应跨度约 48 dB**，从 1.6 kHz 起陡升，到 4.5 kHz 仍在上升（真实谐振点在
  扫频上限之上）。而语音能量集中在 300–1500 Hz，正好落在最弱的 30–48 dB 区间
  —— 这就是"声音小"的根本原因，和"换音色/换音高"都无关。
* 方波的**总**能量跨度只有 5.8 dB：低音的谐波（3–4 kHz 那几根）被高效辐射填平了。
  所以不能拿方波总电平评估带限语音；对语音必须用上表的基频响应。
* 据此试过**共振峰整体上移**（`analysis_sample_rate` 取 4.8 kHz、合成仍 7.2 kHz，
  即 ×1.5）：实测只有 **+0.9 dB** —— F1 上移后仍在弱区，F3 又直接越过 3.6 kHz 的
  奈奎斯特上限。已放弃该方案，配置项保留备用。
* 结论：**软件侧已经到极限**（峰值 96%、压缩到收益拐点、强调对准响应曲线、
  频谱搬家只值 +0.9 dB）。剩下的只能提高驱动电压。

### 由此得到的硬件建议

| 做法 | 预期增益 |
| --- | --- |
| 驱动级 3.3 V → 5 V（三极管/MOS 一级） | +3.6 dB |
| 驱动级 → 12 V | +11 dB |
| 桥接驱动（压电片两端反相） | 再 +6 dB |
| **换小喇叭 + PAM8403 之类功放**（推荐） | +20~30 dB，且音质完全不同 |

固件输出的就是标准 PWM 音频（64.8 kHz 载波、9 位占空比），把同一路信号接到
功放输入即可，不需要改固件。

## 硬件行为

* 采样率 7200 Hz（Timer0 走 1T 模式，重载 60928 = 65536-4608，
  `33177600/4608 = 7200` 正好整除），主循环只等状态，播放全部由中断推进。
* PWM 比较值经 HSPWM 异步窗口写入（与 `CNU_PIE_PWM.c` 的 `PWM_WriteB` 同一套
  时序）。样本只有 8 位、高字节恒为 0，所以每周期只写低字节，避免高低字节
  不同步带来的一次占空比毛刺。
* 主循环不碰 PWM，因此异步窗口不会有两个上下文竞争。
* P35/P36 分别指示当前播的是「六零」版还是「六十」版，两版之间停 800 ms。

## 已知限制与后续可做

1. **音质天花板**：7.2 kHz 采样 + 10 阶 + 100 帧/秒是 TMS5220 级别的参数，
   清晰度够、自然度差。想明显改善就得换硬件（小喇叭 + 功放），或上 16 kHz
   采样并接受更高的中断开销（需要 32 位乘法的替代方案，如 STC32G 的 MDU32
   协处理器——它是 DMA 命令驱动的，不能由 C 直接生成）。
2. **音量**：单端 3.3/5 V 直推压电片，赛场噪声下只适合近距离提示。
   真机上如果觉得轻，优先考虑加一级驱动而不是继续加数字增益（已经贴到
   不削顶的上限）。
3. **共振峰精度**：现在只做了一阶高频提升来补偿压电片低频滚降，
   没有做压电片实测频响的逆滤波。有实测频响后可以在
   `make_voice_params.py` 的 `piezo_response()` 里换成真正的逆滤波。
4. **语料扩展**：`voice.json` 里加一条就是一句话；一句 2.5 秒约 3.3 KB
   flash（12K128 装几十句没问题）。
