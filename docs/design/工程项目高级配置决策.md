## 1. 背景与目标

改造前的工程项目是「强制坦克底盘 + 1–4 套按键/摇杆映射」的配置器：

- 底盘 4 轮、方向、普通速度必填；生成只做 LY/LX 差速混合（`code_generator.dart` 的 `_chassis()`）。
- 动作是单输入 → 单输出（`ActionMapping.key → pin`），参数只是固定控制律里的标量，无法表达多输入混合。
- 4 个底盘电机脚被占用，动作写底盘脚会被校验器拒绝；6 个可驱动电机脚最多只剩 2 个自由脚。
- 摩擦轮角色只是原始占空比输出，没有步兵那套 500 启动 / 1000ms 激活 / ±1 斜坡 / 上限保护。
- `PrepareMode` 不归零底盘槽，切到「取消底盘」模式会残留占空比，存在安全隐患。

本次改造的目标（按优先级）：

1. 让特殊底盘（麦克纳姆轮、全向轮）可以在工程项目里配置，并保留工程项目的通用映射能力；
2. 让工程项目能安全驱动摩擦轮（供特殊步兵/工程使用）；
3. 为高级用户提供「变量 + 表达式」的混控/计算能力（含低自由度机械臂闭式逆解），但必须可控、可校验；
4. 舵轮本期不纳入（评估结论见 §9），机械臂逆解由自由表达式实现、不做内建块（D14）。

**非目标**：6 自由度/数值逆解、闭环定位、任意 C/脚本编程环境、绕过静态校验的自由代码。

## 3. 逐项决策

### D1 底盘控制可选（默认启用）

- 数据模型：`chassis.enabled`（或以「未分配」推断，二选一，推荐显式字段）。启用时四轮 pin/direction、`normal_speed` 必填；不启用时全部可空。
- 校验器：`_robot`/`_chassis` 的必填逻辑按 `enabled` 分支；`actions` 允许使用已释放的原底盘脚；`mode.preserveChassis` 与「模式 1 必须保留左摇杆底盘控制」的规则按 `enabled` 派生（不启用时不再要求）。
- 生成器：`_header` 不再强制解包 `normalSpeed!`；不生成 `CalculateChassis`；冲刺/方向键相关代码条件生成；`PrepareMode` 必须把「被释放的脚」纳入归零逻辑。
- UI：遥控器与底盘页新增开关（默认开）；关闭后隐藏/置灰四轮、速度、冲刺、转向反转；模式页隐藏「保留左摇杆底盘控制」。
- 验收：默认启用（差速）的现有项目生成 C 与 HEX 逐字节不变。

### D2 行字段顺序

- UI 顺序改为：输入 → 输出 → 方向 → 控制方式 → 参数；输出决定角色与控制方式候选，放在方向之前更符合操作顺序。
- 数据字段与字段路径（`modes.<m>.actions.<i>.key/pin/...`）不变。
- 需同步：`_ActionRow` 布局、字段锚点顺序、widget 测试、文档截图与官网演示项目。

### D3 字段改名

- 「按键」→「输入」，「IO」→「输出」。只改展示文案，不改 `key`/`pin` 字段名，避免无谓迁移。
- 同步修改：向导文案、校验消息、文档与 schema 描述、测试断言。

### D4 输入「未指定」

语义（与 D9 规则矩阵配合）：

| 输入 | 输出 | 方向 | 控制方式 | 参数 | 语义 |
| --- | --- | --- | --- | --- | --- |
| 按键/轴 | 引脚 | 显示（摩擦轮模式隐藏） | 现有模式 + 摩擦轮模式（仅摩擦脚） | 数值（现有固定律） | 现有动作 |
| 未指定 | 引脚 | 隐藏 | 隐藏（固定为表达式） | 表达式 | 每周期把表达式写入输出值（真值） |
| 按键/轴 | 整数/有理数 | 隐藏 | 隐藏 | 不使用 | 变量 = 输入值 |
| 未指定 | 整数/有理数 | 隐藏 | 隐藏 | 表达式 | 变量 = 表达式（也可用于定义常量） |

- 校验器必须拒绝非法组合（例如输入未指定却选了「单次/持续」、变量行带方向等）。
- 生成器里所有 `a.key!` 的强制解包要改为按行语义分支。

### D5 输出「整数 / 有理数」与变量

- 输出下拉增加「整数」「有理数」，选中后新增「变量名」字段（用户输入 C 标识符）。
- 类型：整数用 `int32_t`（SDCC C251 的 `int` 为 16 位且乘法不提升，不能用 16 位）；有理数用 `float`（不引入 `double`）。
- 作用域（Q7）：
  - 同一模式内，同一变量名最多出现一次（重复定义是错误）。
  - 只在一个模式出现的变量 → 该模式局部变量，在生成的模式函数开头声明（C89 声明前置），初值 0。
  - 同名变量出现在 2 个及以上模式 → 提升为全局变量，文件作用域声明，初值 0；各模式中的类型必须一致；在未赋值的周期保持上一次值。
  - 局部变量仅本模式可用；全局变量可在任意模式引用。
- 校验：C 关键字、生成符号保留字（`dutyOfMotor`、`mainServoDuty`、`maxSpeed`、`ultraSpeed`、`Channal`、`friction*` 等）、内置输入名冲突、作用域唯一、先定义后使用、未使用告警。
- 生成：变量名统一加前缀（如 `v_`）；整数/浮点隐式转换要显式化并给出告警（例如浮点赋给整数会截断）。

### D6 参数 = 括号内右值表达式（仅输入未指定）

- 「输入未指定」的行：参数统一按右值处理，生成 `dutyOfMotor[slot] = (表达式);`（引脚行）或 `v_xxx = (表达式);`（变量行）；常量就是字面量表达式（`175` → `(175)`），因此常量与表达式在**这些行**里等价。
- 「输入有值 + 输出引脚 + 现有控制方式（direct/speed/accelerate/single/continuous）」：参数仍按现有固定律里的**数值**语义处理（如 `duty = x*param/2047`），不是整条右值（Q5）。
- 「输入有值 + 输出变量」：参数不使用，变量 = 输入值。
- 输出单位按角色定义：电机 = duty（±10000）；舵机 = 角度（−90~90，生成器自动换算 250–1250）；摩擦轮 = 油门 %（0–100）；变量 = 声明类型。生成器统一做类型转换、钳位与异常值处理。

### D7 工程摩擦轮控制语义

- 触发条件：输出为 P64/P66、引脚角色为「摩擦轮」、所属 PWM 组频率为 50Hz（不满足报 Error）。
- 油门共享（Q4）：P64/P66 共用**一个**油门电平（0–100），与步兵一致；两个引脚各自的满油占空比上限（500–800 整百）配在「PWM 与引脚」页，按各自上限把共享油门映射为各自的目标占空比。
- 控制方式（实施期修订，新增 4 个 `ControlMode` 值；旧控制方式在摩擦脚上保留 raw duty 兼容金样并给 Warning）：
  - **启停** `frictionToggle`：按键边沿；按一下把目标油门设为参数值（1–100），再按一下设 0；无方向；
  - **单次** `frictionStep`：按键边沿；目标油门 ±参数（1–100 %/次），方向决定加减；
  - **持续** `frictionContinuous`：按住期间按参数（1–100 %/秒）持续加减，方向决定加减；按 50 循环/秒换算并累加余数；
  - **摇杆增量** `frictionAxis`：仅轴输入；满杆按参数（1–100 %/秒）加减，方向由轴符号决定；无方向字段。
- 方向：启停行与摇杆增量行不显示方向；单次/持续行保留方向（正=加速、反=减速）。Dir 帧对摩擦轮固定为 1。
- 生成安全栈（移植步兵实现）：0→非 0 时两个摩擦轮先给 500 启动占空比保持 1000ms 完成电调激活；之后各自占空比 ±1/主循环向目标逼近；目标 0 走停机斜坡，不得直接断；上限保护；可选蜂鸣器反馈。
- **斜坡的适用范围**：只有摩擦轮走「目标油门 → 每脚目标占空比 → 实际占空比」这个斜坡子系统；电机/舵机（包括表达式行）不经过该斜坡，直接输出真值。
- 状态：共享油门 + 每脚实际占空比；模式切换时保持；`PrepareMode` 不得把摩擦轮槽直接归零；按键状态需像现有舵机按键一样做模式切换同步，避免切模式后误触发。
- 输入类型与控制方式（Q10/D15）：摇杆输入只允许「摇杆增量」；按键输入只允许「启停/单次/持续」。启停是摩擦轮专用模式。摩擦轮脚禁止表达式行直接写占空比（防止绕过安全栈）。

### D8 输出语义：表达式行直接写真值（无通用斜坡）

- 表达式行/执行行（输入未指定 → 引脚）每周期计算一次，**直接写输出真值**，不维护 target/actual 状态：
  - 电机：`dutyOfMotor[slot] = (表达式);`，按角色钳位 ±10000；方向位仍由写入值符号决定。
  - 舵机：表达式输出角度（−90~90），生成器换算为 250–1250 的绝对占空比并钳位；舵机自身的机械/内部斜坡负责过渡，应用层不做软件斜坡。
  - 摩擦轮：禁止表达式行直接写（必须走 D7 安全栈）。
- 作用范围与兼容：只影响新增的表达式/计算行；旧的 direct/speed/accelerate/single/continuous 语义与现有输出路径不变，保证旧项目行为与金样逐字节不变。
- **不引入「所有输出统一斜坡」**：电机/舵机若需要软启动/限速，继续用现有输入行的 `accelerate`/`incremental` 等模式；表达式行没有软件平滑（上电或切模式后首个执行周期就是表达式算出的值，可能是阶跃）。
- 模式切换：
  - 摩擦轮：状态（共享油门 / 实际占空比）跨模式保持（D7 例外，`PrepareMode` 不归零）。
  - 其他引脚：沿用现有 `PrepareMode` 行为——新模式下未映射的电机/摩擦轮/抖动脚清零，舵机保持最后位置。
  - 原 Q2「均保持」不再有「所有输出的 target」这一对象；若要进一步改成「未映射电机也保持最后值」，会改变现有行为且有残留运动风险，需单独确认（见 R7）。
- 发送帧（Dir/Duty）与主控舵机更新逻辑保持现状，不因表达式行改变。

### D9 不新增行类型

- 不引入显式「行类型」下拉；行类型由（输入是否未指定、输出是引脚还是变量、控制方式）隐式决定。
- 必须提供 §4 的规则矩阵，并在 UI 上按组合动态显示/隐藏/禁用字段；校验器对非法组合给出字段级错误。
- 理由：减少控件与用户理解成本；代价是隐式规则多，必须靠校验与文案补足。

### D10 受限表达式与静态校验（已确认）

- 表达式语言：单条表达式；允许字面量、变量、内置输入（LX/LY/RX/RY/按键）、`+ - * / %`、括号、比较（`> < >= <= == !=`）、逻辑（`&& || !`）、三元（`?:`）、白名单函数（`min/max/abs/sign/atan2/sqrt` 等）与常量 π；禁止 `;`、`{`、`}`、`#`、赋值、逗号、指针、下标、白名单外函数。
- 主校验（全平台，即时）：Dart 解析器 + 变量/类型/单位/白名单/先定义后使用/除零常量检查 + 试算预览。
- 次校验（仅桌面）：把表达式放进声明齐备的小编译单元用 SDCC/Keil 编译，或作为生成前完整构建门禁；需要错误行号到字段路径的映射，并区分「表达式错误」与「工具链/环境错误」。
- 平台限制（Q8 已接受）：Web 版与 Android Release 没有本地编译流水线，只做 Dart 校验；不承诺编译门禁。
- 生成端：表达式按 `int32_t`/`float` 求值，自动括号、显式类型转换；输出按角色钳位；处理 NaN/Inf/除零/负数开方（静态拒绝或生成守卫）；C89 声明前置；数学库函数名在 SDCC（`atan2f/sqrtf`）与 Keil（`atan2/sqrt`）间做可移植宏。
- 风险接受（Q6）：允许比较/三元，接受「编译通过但运行期仍可能出错」的残余风险；通过试算、实机限速与文档提示兜底。

### D13 变量作用域（Q7）

- 每模式内同一变量名最多出现一次；只在一个模式出现 → 局部变量；同名出现在多个模式 → 全局变量（见 D5）。
- 全局变量的值在模式切换时保持；未在当前模式赋值的周期沿用上一次值。这允许跨模式的共享量/常量，也意味着变量可以被当作轻量状态使用，需在文档中明确。

### D14 机械臂逆解（Q9）

- 不做内建机械臂逆解块；由用户用变量 + 表达式实现。
- 能力边界：2–4 自由度闭式逆解可行（需要 `atan2/sqrt/min/max`、变量与常量）；6 自由度一般逆解、数值迭代、闭环、轨迹规划不可行。
- 交付要求：提供示例项目与公式模板、关节零位/限位/工作空间钳位的写法说明、实机限速建议；不承诺所有用户都能正确编写。

### D15 输入类型与控制方式约束（Q10）

- 保留「加速/减速」，对应摩擦轮的「单次」与「持续」两种按键控制方式。
- 摇杆（轴）输入：摩擦轮只允许「摇杆增量」；按键输入：摩擦轮只允许「启停/单次/持续」。
- 适用范围：仅约束摩擦轮与新增目标行；既有工程动作（摇杆 speed/accelerate、按键 direct 等）保持现状，避免破坏已有项目（R4 已确认）。实现时把该矩阵固化进 §4 规则表与校验器。
- 实施期修订：摩擦轮专用 4 个控制方式为 `frictionToggle/frictionStep/frictionContinuous/frictionAxis`；参数单位分别为 目标%/次·%/秒·满杆%/秒。

## 4. 字段/语义规则矩阵（D9 的落地）

| 输入 | 输出 | 方向 | 控制方式 | 参数 | 变量名 | 允许的表达式 |
| --- | --- | --- | --- | --- | --- | --- |
| 按键/轴 | 引脚 | 显示（启停/摇杆增量隐藏，单次/持续显示） | 现有模式；摩擦轮 4 个专用模式 | 数值（现有语义；摩擦轮按单位） | — | 否（仅未指定输入可写表达式） |
| 未指定 | 引脚 | 隐藏 | 隐藏 | 表达式 | — | 是（D10 白名单） |
| 按键/轴 | 整数/有理数 | 隐藏 | 隐藏 | 不使用 | 必填 | 否 |
| 未指定 | 整数/有理数 | 隐藏 | 隐藏 | 表达式 | 必填 | 是（可用作常量定义） |

## 5. 表达式与静态校验的实施要点（D10）

- Dart 侧先实现：词法/语法解析 → AST → 变量与函数检查 → 类型/单位推断 → 常量折叠（除零等）→ 生成 C（括号、显式转换、钳位）。
- 桌面编译门禁复用 `pieblock_toolchain`；错误行号通过生成映射表回填到字段路径；编译失败不阻塞本地保存，但阻塞进入生成/烧录步骤。
- Web/Android 只做 Dart 校验，UI 明示「本平台不做编译检查」。
- 表达式数量/函数调用次数需设上限或估算耗时，避免 20ms 主循环超时；生成后检查 Flash 余量（app 区 64KB）。

## 6. 关键约束（来自现有硬件/代码）

- 扩展板 8 路 + 主控 2 路舵机口；PWMA（P60/P62/P64/P66）与 PWMB（P74/P75/P76/P77）**组内同频**，50Hz 给舵机/摩擦轮、10000Hz 给平滑电机。
- 拓展板协议纯写、无回读/无编码器 → 只能开环控制。
- SDCC C251：`int` 16 位、乘法不提升、C89 声明前置；app 区 Flash 上限 64KB，浮点数学库约 +4.6KB，需用 Android 金样构建实测余量。
- 主循环固定约 20ms（两帧各 5ms + 10ms 延时）；模式切换提示音最长阻塞约 2.1s，期间不更新输出。
- 现有金样 `tools/android_sdcc_baseline.json` 的 6 个 HEX sha 是验收门禁；差速默认分支必须逐字节不变。

## 9. 能力边界（本次评估结论）

| 需求 | 结论 | 说明 |
| --- | --- | --- |
| 差速底盘（现状） | 保持 | 默认启用，生成逐字节不变 |
| 麦克纳姆轮 / 全向轮 | 可支持 | 底盘可选 + 混控表达式（线性组合、钳位）；动态归一化只能固定缩放+钳位近似 |
| 舵轮 | 本期不做 | 需要 atan2/模长/±90° 翻转/限位，且 4 驱+4 转占满 8 路，带云台/拨弹/摩擦轮的步兵形态物理不可行；用户已表示优先级低 |
| 摩擦轮 | 可支持 | D7 启停/增量 + 安全栈；不可当驱动轮（单向+慢斜坡） |
| 机械臂逆解（2–4 DOF 闭式） | 有限支持（用户自写表达式） | 需变量 + 常量 + 函数白名单；可维护性/安全性由用户承担；不内建 |
| 6 自由度/数值 IK、闭环、轨迹规划 | 不支持 | 无状态/无循环/无回读，表达式模型与硬件都不满足 |
| 「所有构型」 | 不承诺 | 受 8+2 路、组内同频、无编码器、20ms、64KB 等硬约束限制 |

## 12. 风险与安全

- **表达式是用户代码**：即使限制为单表达式，也可能出现逻辑错误、溢出、NaN；Q6 已接受残余风险，仍需试算 + 编译门禁 + 实机限速兜底。
- **表达式行直接写真值**：没有软件斜坡，上电或切模式后首个执行周期就是表达式算出的值，可能出现阶跃；需要软启动时用现有 `accelerate` 行（仅输入有值可用）或在文档中说明。
- **原 Q2「均保持」已随通用斜坡撤销**：摩擦轮状态跨模式保持；电机/舵机沿用现有 `PrepareMode` 行为。已确认（R7）：未映射电机清零、舵机保持；若后续要求电机保持最后值，属于行为变更且有残留运动风险。
- **全局变量可作轻量状态**：已接受（R3）；类型不一致报 Error，初值 0，跨模式保持上次值。
- **安全红线**：摩擦轮 50Hz、500 启动、1000ms 激活、≤100 duty/s、必须有关闭逻辑、上限 1100；任何「直接写占空比」的入口都不能碰摩擦轮脚。
- **模式切换**：提示音阻塞约 2.1s 期间输出不更新；高级行加入后需要重新评估。
- **平台差异**：Web/Android 无本地工具链，表达式校验能力降级并明示。
- **产品定位**：高级行/表达式建议默认隐藏；普通向导仍以内建、可静态校验的能力为主。
