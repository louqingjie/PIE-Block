> 状态：**草案（已评估，待评审）**
> 日期：2026-10-24
> 范围：`ProjectKind.engineer` 的底盘、摩擦轮、动作映射、变量/表达式与静态检查
> 相关代码：`packages/pieblock_core/lib/src/{models,validator,code_generator}.dart`、`lib/src/wizard/wizard_pages_{engineer,pwm,remote}.dart`
> 相关文档：[RM 电控指南](../guides/RM电控指南.md)、[机械拓展板使用指南](../guides/机械拓展板使用指南%20.md)、[STC32G 固件约束](../reference/STC32G固件约束.md)、[项目文件格式](../reference/Flutter项目文件格式.md)

## 1. 背景与目标

改造前的工程项目是「强制坦克底盘 + 1–4 套按键/摇杆映射」的配置器：

- 底盘 4 轮、方向、普通速度必填；生成只做 LY/LX 差速混合（`code_generator.dart` 的 `_chassis()`）。
- 动作是单输入 → 单输出（`ActionMapping.key → pin`），参数只是固定控制律里的标量，无法表达多输入混合。
- 4 个底盘电机脚被占用，动作写底盘脚会被校验器拒绝；6 个可驱动电机脚最多只剩 2 个自由脚。
- 摩擦轮角色只是原始占空比输出，没有步兵那套 500 启动 / 1000ms 激活 / ±1 斜坡 / 上限保护。
- `PrepareMode` 不归零底盘槽，切到「取消底盘」模式会残留占空比，存在安全隐患。

本次改造的目标（按优先级）：

1. 让特殊底盘（麦克纳姆轮、全向轮）可以在工程项目里配置，并保留工程项目的通用映射能力；
2. 让工程项目能安全驱动摩擦轮（供特殊步兵/工程使用）；
3. 为高级用户提供「变量 + 表达式」的混控/计算能力（含低自由度机械臂闭式逆解），但必须可控、可校验；
4. 舵轮本期不纳入（评估结论见 §8），机械臂逆解建议后续内建（见 §8）。

**非目标**：6 自由度/数值逆解、闭环定位、任意 C/脚本编程环境、绕过静态校验的自由代码。

## 3. 逐项决策

### D1 底盘控制可选（默认启用）

- 数据模型：`chassis.enabled`（或以「未分配」推断，二选一，推荐显式字段）。启用时四轮 pin/direction、`normal_speed` 必填；不启用时全部可空。
- 校验器：`_robot`/`_chassis` 的必填逻辑按 `enabled` 分支；`actions` 允许使用已释放的原底盘脚；`mode.preserveChassis` 与「模式 1 必须保留左摇杆底盘控制」的规则按 `enabled` 派生（不启用时不再要求）。
- 生成器：`_header` 不再强制解包 `normalSpeed!`；不生成 `CalculateChassis`；冲刺/方向键相关代码条件生成；`PrepareMode` 必须把「被释放的脚」纳入归零逻辑。
- UI：遥控器与底盘页新增开关（默认开）；关闭后隐藏/置灰四轮、速度、冲刺、转向反转；模式页隐藏「保留左摇杆底盘控制」。
- 验收：默认启用（差速）的现有项目生成 C 与 HEX 逐字节不变。

### D2 行字段顺序

- UI 顺序改为：输入 → 输出 → 方向 → 控制方式 → 参数；输出决定角色与控制方式候选，放在方向之前更符合操作顺序。
- 数据字段与字段路径（`modes.<m>.actions.<i>.key/pin/...`）不变。
- 需同步：`_ActionRow` 布局、字段锚点顺序、widget 测试、文档截图与官网演示项目。

### D3 字段改名

- 「按键」→「输入」，「IO」→「输出」。只改展示文案，不改 `key`/`pin` 字段名，避免格式升级带来的无谓迁移。
- 同步修改：向导文案、校验消息、文档与 schema 描述、测试断言。

### D4 输入「未指定」

语义（与 D9 规则矩阵配合）：

| 输入 | 输出 | 方向 | 控制方式 | 参数 | 语义 |
| --- | --- | --- | --- | --- | --- |
| 按键/轴 | 引脚 | 显示 | 现有模式 + 摩擦轮模式（仅摩擦脚） | 数值/表达式（见 D6） | 现有动作 |
| 未指定 | 引脚 | 隐藏 | 隐藏（固定为表达式） | 表达式 | 每周期把表达式写入目标值 |
| 按键/轴 | 整数/有理数 | 隐藏 | 隐藏 | 不使用 | 变量 = 输入值 |
| 未指定 | 整数/有理数 | 隐藏 | 隐藏 | 表达式 | 变量 = 表达式（也可用于定义常量） |

- 校验器必须拒绝非法组合（例如输入未指定却选了「单次/持续」、变量行带方向等）。
- 生成器里所有 `a.key!` 的强制解包要改为按行语义分支。

### D5 输出「整数 / 有理数」与变量

- 输出下拉增加「整数」「有理数」，选中后新增「变量名」字段（用户输入 C 标识符）。
- 类型：整数用 `int32_t`（SDCC C251 的 `int` 为 16 位且乘法不提升，不能用 16 位）；有理数用 `float`（不引入 `double`）。
- 作用域：建议**每模式局部变量**，在生成的模式函数开头声明（C89 要求声明前置），按行序赋值；每周期重算，**无跨周期状态**。
- 校验：C 关键字、生成符号保留字（`dutyOfMotor`、`mainServoDuty`、`maxSpeed`、`ultraSpeed`、`Channal`、`friction*` 等）、内置输入名冲突、同作用域唯一、先定义后使用、不允许循环引用、未使用告警。
- 生成：变量名统一加前缀（如 `v_`）避免与生成代码碰撞；整数/浮点隐式转换要显式化并给出告警（例如浮点赋给整数会截断）。

### D6 参数 = 括号内右值表达式

- 对「输入未指定」与「输出为变量」的行：参数统一按右值处理，生成 `目标 = (表达式);`；常量就是字面量表达式（`175` → `(175)`），因此常量与表达式在**这些行**里等价。
- 对「输入有值 + 输出引脚 + 现有控制方式（direct/speed/accelerate/single/continuous）」：参数仍按现有固定律里的**数值**语义处理（如 `duty = x*param/2047`），不是整条右值。若未来要统一为右值，会改变现有配置语义，需单独评审。
- 表达式边界（见 D10）：单条表达式，不含分号/花括号/预处理指令；默认禁止赋值、逗号、指针、下标、强转；函数走白名单。
- 输出单位按角色定义：电机 = duty（±10000）；舵机 = 角度（−90~90，生成器自动换算 250–1250）；摩擦轮 = 油门 %（0–100）；变量 = 声明类型。生成器统一做类型转换、钳位与异常值处理。

### D7 工程摩擦轮控制语义

- 触发条件：输出为 P64/P66、引脚角色为「摩擦轮」、所属 PWM 组频率为 50Hz（不满足应报 Error，而不是现在的 Warn）。
- 新增控制方式：
  - **启停**：按一下把目标油门设为参数值，再按一下设 0；边沿触发。
  - **油门增量**：按一下把目标油门加减参数值（clamp 0–100），边沿触发。
- 方向字段删除（数据置空），Dir 帧对摩擦轮固定为 1；参数为油门值（启停建议 1–100，0 无意义；增量 1–100）。
- 每脚配置满油上限（500–800 整百），建议加在 PWM 页或摩擦轮小节；目标油门按上限映射为目标占空比。
- 生成安全栈（移植步兵实现）：0→非 0 先给 500 启动占空比保持 1000ms 完成电调激活；之后占空比 ±1/主循环向目标逼近；目标 0 走停机斜坡，不得直接断；上限保护；可选蜂鸣器反馈。
- 状态：建议 P64/P66 各自独立（目标油门/实际占空比）；若复刻步兵的共享油门，需在配置与文档中明确。
- 模式切换：摩擦轮状态跨模式保持；`PrepareMode` 不得把摩擦轮槽直接归零；按键状态需像现有舵机按键一样做模式切换同步，避免切模式后误触发。
- 表达式行/执行行不得直接写摩擦轮脚（防止绕过安全栈）。

### D8 斜坡目标架构

- 新表达式行、启停、增量写的是**目标值**，不直接写占空比/真值；生成器为每个输出维护 target/actual 状态与斜坡速率，每个主循环把 actual 向 target 逼近一次。
- 作用范围：只对新行生效；旧的 direct/speed/accelerate/single/continuous 仍写真实值，保证现有项目行为与金样不变。
- 速率：按角色给出默认值（电机 duty/周期、舵机 °/周期；摩擦轮固定 ±1 duty/周期的安全斜坡），可后续开放配置。**具体默认值待实机标定。**
- 初始化：上电 actual = 0（电机/摩擦轮）、舵机 = 中位；首帧按斜坡逼近目标。
- 模式切换：逐角色定义 target 策略（建议电机 target 清零、舵机保持、摩擦轮保持），并改写 `PrepareMode`，不要直接写 `dutyOfMotor = 0`。
- 发送帧（Dir/Duty）与主控舵机更新改用 actual；方向位由 actual 符号决定。
- 同一引脚在同一模式内不允许既被旧行直接写、又被目标行写；跨模式复用时需定义 actual 的初始化/收敛策略。

### D9 不新增行类型

- 不引入显式「行类型」下拉；行类型由（输入是否未指定、输出是引脚还是变量、控制方式）隐式决定。
- 必须提供 §4 的规则矩阵，并在 UI 上按组合动态显示/隐藏/禁用字段；校验器对非法组合给出字段级错误。
- 理由：减少控件与用户理解成本；代价是隐式规则多，必须靠校验与文案补足。

## 5. 表达式与静态校验（D10，待确认）

**建议方案：受限表达式 + 两级校验**，而不是任意 C 语句 + 只靠编译。

- 表达式语言：单条表达式；允许字面量、变量、内置输入（LX/LY/RX/RY/按键）、`+ - * / %`、括号、比较/三元（按需）、白名单函数（`min/max/abs/sign/atan2/sqrt` 等）与常量 π；禁止 `;`、`{`、`}`、`#`、赋值、逗号、指针、下标、强转、白名单外函数。
- 主校验（全平台，即时）：Dart 解析器 + 变量/类型/单位/白名单/先定义后使用/除零常量检查 + 试算预览。
- 次校验（仅桌面）：把表达式放进声明齐备的小编译单元用 SDCC/Keil 编译，或作为生成前完整构建门禁；需要错误行号到字段路径的映射，并区分「表达式错误」与「工具链/环境错误」。
- 平台限制：Web 版与 Android Release 没有本地编译流水线，只能依赖 Dart 校验；不能把编译检查当作全平台能力。
- 生成端：表达式按 `int32_t`/`float` 求值，自动括号、显式类型转换；输出按角色钳位；处理 NaN/Inf/除零/负数开方（静态拒绝或生成守卫）；C89 声明前置；数学库函数名在 SDCC（`atan2f/sqrtf`）与 Keil（`atan2/sqrt`）间做可移植宏。
- 明确「编译通过 ≠ 逻辑正确/安全」：编译检查只能兜语法、符号、类型与链接，兜不住溢出、NaN、20ms 超时与实机安全问题。

## 6. 关键约束（来自现有硬件/代码）

- 扩展板 8 路 + 主控 2 路舵机口；PWMA（P60/P62/P64/P66）与 PWMB（P74/P75/P76/P77）**组内同频**，50Hz 给舵机/摩擦轮、10000Hz 给平滑电机。
- 拓展板协议纯写、无回读/无编码器 → 只能开环控制。
- SDCC C251：`int` 16 位、乘法不提升、C89 声明前置；app 区 Flash 上限 64KB，浮点数学库约 +4.6KB，需用 Android 金样构建实测余量。
- 主循环固定约 20ms（两帧各 5ms + 10ms 延时）；模式切换提示音最长阻塞约 2.1s，期间不更新输出。
- 现有金样 `tools/android_sdcc_baseline.json` 的 6 个 HEX sha 是验收门禁；差速默认分支必须逐字节不变。

## 8. 能力边界（本次评估结论）

| 需求 | 结论 | 说明 |
| --- | --- | --- |
| 差速底盘（现状） | 保持 | 默认启用，生成逐字节不变 |
| 麦克纳姆轮 / 全向轮 | 可支持 | 底盘可选 + 混控表达式（线性组合、钳位）；动态归一化只能固定缩放+钳位近似 |
| 舵轮 | 本期不做 | 需要 atan2/模长/±90° 翻转/限位，且 4 驱+4 转占满 8 路，带云台/拨弹/摩擦轮的步兵形态物理不可行；用户已表示优先级低 |
| 摩擦轮 | 可支持 | D7 启停/增量 + 安全栈；不可当驱动轮（单向+慢斜坡） |
| 机械臂逆解（2–4 DOF 闭式） | 有限支持 | 变量+常量+函数白名单可写；但可维护性/安全性差，建议后续做内建机械臂块（参数：连杆长、关节脚、零位/限位、分支） |
| 6 自由度/数值 IK、闭环、轨迹规划 | 不支持 | 无状态/无循环/无回读，表达式模型与硬件都不满足 |
| 「所有构型」 | 不承诺 | 受 8+2 路、组内同频、无编码器、20ms、64KB 等硬约束限制 |

## 9. 实施顺序

1. **地基**：D1 底盘可选 + D2/D3 字段顺序与改名；formatVersion 16→17、模板重存、默认差速金样 sha 不变。

- 文档：`docs/reference/Flutter项目文件格式.md`、`docs/reference/schemas/*.json`、本文件、`docs/README.md`。

**验收**

- 旧配置（差速、默认底盘）生成的 C 与 6 个金样 HEX sha 不变。
- 新增示例：关闭底盘 + 4 路麦轮混控表达式，SDCC 与 Keil 均可编译；生成代码含目标/斜坡逻辑且输出钳位正确。
- 摩擦轮：生成代码包含 500 启动、1000ms 激活、±1 斜坡、停机斜坡、上限；参数越界/频率不符/非摩擦脚配置均报错。
- 表达式：非法语法、未定义变量、白名单外函数、除零常量、类型错误均可定位到字段；桌面编译门禁可用。
- 模式切换：不残留旧占空比；摩擦轮状态按定义保持/斜坡。

## 11. 风险与安全

- **表达式是用户代码**：即使限制为单表达式，也可能出现逻辑错误、溢出、NaN、死循环（若未来放开函数调用）；必须以 Dart 校验 + 试算 + 编译门禁 + 实机限速共同兜底。
- **安全红线**：摩擦轮 50Hz、500 启动、1000ms 激活、≤100 duty/s、必须有关闭逻辑、上限 1100；任何「直接写占空比」的入口都不能碰摩擦轮脚。
- **模式切换**：提示音阻塞约 2.1s 期间输出不更新；高级行与新斜坡加入后需要重新评估。
- **平台差异**：Web/Android 无本地工具链，表达式校验能力必须降级并明示。
- **产品定位**：高级行/表达式建议默认隐藏；普通向导仍以内建、可静态校验的能力为主，避免削弱「零编程 + 静态检查」的卖点。
