# 汇编生成器（试点：音乐项目）

`CodeGenerator` 除默认的 C 输出外，新增了**直接生成汇编**的输出目标（`OutputTarget.asm`）。
试点阶段仅音乐项目支持：生成一份与 C 版 `main.c` **行为完全一致**、可直接参与
SDCC 构建管线（sdas251 汇编 → 链接 → HEX）的 `main.asm`，同时保持教学可读性
（中文注释、函数与 C 版一一对应）。

本文件记录生成器依赖的 C251 调用约定调研结论与验证方法，
后续把汇编输出推广到步兵/工程/调试项目时直接复用。

## 使用方式

- Dart 侧：`CodeGenerator.generate(config, target: OutputTarget.asm)`；
  `CodeGenerator.asmSupported(kind)` 查询某项目类型是否支持。
- UI：向导「生成代码」页在支持的项目类型上显示「输出语言：C 代码 / 汇编」切换，
  导出文件名相应为 `main.c` / `main.asm`。
- 构建管线：`BuildRequest` 新增 `outputTarget` 字段；桌面子进程 SDCC 管线
  对主源文件改用 `sdas251 -l -o <object> <source>` 汇编，其余源文件仍由 sdcc 编译，
  链接与产物校验逻辑不变。
- 端到端冒烟：`packages/pieblock_toolchain/tool/compile_asm_smoke.dart`
  （需 vendored 工具链与固件资源，在仓库内运行）。

## C251 调用约定速查（实测自 vendored SDCC）

以下结论通过 `sdcc -S`（`-mmcs251 --model-large --stack-auto --opt-code-size --constseg CSEG`，
与 `stc32g_sdcc/build_manifest.json` 的编译参数一致）对小片段生成的汇编实测得出，
并已在本地完成汇编、链接与 HEX 校验。

1. **符号命名**：C 符号在汇编中多一个下划线前缀（`Ms_Delay` → `_Ms_Delay`）。
2. **第一个参数用寄存器传递**：
   - 8 位（如 `PWM_CHN_PIN_enum` 通道号）→ `DPL`；
   - 16 位（如 `Ms_Delay` 的毫秒数）→ `DPTR`（`DPL`=低字节，`DPH`=高字节）；
   - 32 位（如 `PWM_Init` 的频率/占空比）→ `DPL`=最低字节，`DPH`、`B` 依次更高，`A`=最高字节。
3. **其余参数从右往左逐个压栈**，多字节值高位字节在前（大端）；
   调用方负责清理栈参数（`dec spx,#4`，每 4 字节一条）。
   因此**保护现场用的 push 必须放在参数压栈之前**，否则会被 `dec spx` 清理掉。
4. **调用与返回**：统一 `ecall` / `eret`；尾调用可用 `ejmp`（省一次返回）。
5. **易失寄存器**：`A`、`B`、`DPTR/DPX`、`R0~R7` 都可能被被调用的 C 函数改写；
   跨调用需要保留的值先 `push`、调用后 `pop`。`push/pop` 使用 `arN` 形式
   （R0~R7 的直接地址别名，`ar0 = 0x00` … `ar7 = 0x07`，生成文件头部有定义）。
6. **代码空间常量表**位于 24 位线性地址空间（`--code-loc 0xff0000` 起）。
   取表模式（与编译器一致）：
   ```asm
   mov  dpl, r_low        ; 地址低字节
   mov  dph, r_mid        ; 地址中字节
   mov  dpxl, a           ; 地址高字节（由 addc a,#(sym >> 16) 得到）
   mov  dr28, dpx
   clr  a
   movc a, @a+dptr        ; 读一个字节
   inc  dpx               ; 指针前移（24 位）
   ```
   16 位常量按**大端**存放（高字节在低地址），地址计算使用
   `add a,#sym`（低字节）、`addc a,#(sym >> 8)`、`addc a,#(sym >> 16)` 三段进位链。
   注意：可重定位标签**不能**用 `#(sym & 0xff)` 掩码形式（重定位错误），
   低字节直接写 `#sym`。
7. **main 模块必须提供的骨架**（替换 main.c 时缺一不可，均实测自 SDCC 输出）：
   - `HOME` 段：`__interrupt_vect`（`ljmp __sdcc_mcs251_reset_trampoline` +
     `ejmp __sdcc_gsinit_startup`）和 `__sdcc_program_startup`（`ecall _main`）；
   - `GSFINAL` 段：`ejmp __sdcc_program_startup`（启动链终点，
     其余模块的 GSFINAL 均为空，只有 main 模块提供跳转）；
   - `SSEG` 段：`__start__stack:` + `.ds 1`（运行库据此初始化堆栈指针，
     缺失会报 `Undefined Global __start__stack`）；
   - `XSEG` 段：全局变量（C 版静态初始化的全局在 asm 中改为显式写入，
     等价于运行库清零后再赋值）。
8. **汇编器语法注意**（sdas251 / asxxxx 系）：
   - 等值符号用 `NAME = value`；表达式用括号包裹（`#(MUSIC_DUTY_ON >> 8)`）；
   - `.globl` 既用于导出本地定义的符号，也用于声明外部引用，
     未声明的未定义符号会报 `<u> undefined symbol`；
   - `sdas251 -l -o <obj>.rel <src>.asm` 会把 `.lst` 写到 `-o` 指定的目录，
     链接器（sdld）会在工作目录查找 `<模块名>.lst` 更新行号，缺失会导致
     链接失败（exit 1）——构建管线因此保持 `-l` 选项。

## 与 C 版的对应关系（音乐项目）

| C 函数 | 汇编标号 | 说明 |
| --- | --- | --- |
| `Music_Wait(uint32_t)` | `_Music_Wait` | 32 位比较/减法用借位链实现，超长延时拆成 65535ms 段 |
| `Music_Stop(void)` | `_Music_Stop` | 静音 = 频率 1000、占空比 0 |
| `Music_PlaySegment(uint16_t)` | `_Music_PlaySegment` | 休止走静音序列，其余查频率表；参数保护先于压栈 |
| `Music_PlayOnce(void)` | `_Music_PlayOnce` | 16 位循环计数（`inc` 不影响标志位，需显式判断回绕） |
| `All_Init(void)` | `_All_Init` | 额外显式写 `Channal = 36`（C 版由静态初始化完成） |
| `main(void)` | `_main` | 与 C 版相同的主循环 |

数据表：C 版的 `musicFrequencies[128]`（MIDI 音符 → 频率）与
`musicSegments[]`（时长 + 音符）在汇编中对应 `CSEG` 常量表
`_musicFrequencies`（16 位大端）与平行数组 `_musicSegmentDurations`（32 位大端）、
`_musicSegmentNotes`（每段一字节，0=休止）。平行数组取代了 C 的结构体布局，
数据与行为等价，且省去结构体偏移计算，更利于教学。

## 验证情况与边界

- ✅ 生成产物可被 `sdas251` 汇编、与真实固件库（GPIO/PWM/startup/isr + mcs251 运行库）
  链接，通过 `IntelHexValidator` 的 HEX/MAP 布局校验（桌面端子进程管线端到端）。
- ✅ 单元测试覆盖汇编输出的关键结构（见 `pieblock_core_test.dart` 生成器组）。
- ⚠️ 运行期行为无法在本机验证（无 C251 模拟器）：调用约定与指令序列均照抄
  编译器对相同操作的产物，最终等价性需真机烧录确认。
- 汇编输出的 HEX 构建依赖桌面子进程管线；Android 内嵌 SDCC 管线尚未放行
  `sdas251`（`BuildRequest.outputTarget == asm` 时会明确拒绝）。
