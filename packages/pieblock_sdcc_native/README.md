# PIE-Block Android SDCC FFI

This package owns the versioned C ABI and the Android compiler-service bridge
for the embedded MCS-251 toolchain. Flutter never loads the compiler library:
the non-exported `SdccCompilerService` loads it in the private `:compiler`
process. No compiler executable is released to a writable directory.

The ABI wrapper, request ownership, event queue, cancellation and single-build
mutex are implemented. `pieblock_sdcc_pipeline.c` is the integration seam for
the preprocessor, compiler, assembler and linker stages from the pinned
`sdcc-c251` fork.

The four stages are linked for both target ABIs. The current release gate still
returns `PB_SDCC_UNAVAILABLE`: an ARM64 device completes the first translation
unit, but the embedded GCC preprocessor still fails to return on its second
translation unit even after `toplev.finalize()` cleanup. The gate remains closed
until that reset problem and the Windows/Android byte-for-byte golden matrix
pass. A failed self-test or compiler crash therefore cannot create a cacheable
firmware artifact.

## Fixed baseline

- SDCC fork commit: `912a589d4080c9cd5c5c1faf871c62dd5023580d`
- C ABI: `4`
- AIDL service protocol: `1`
- Android API: `24`
- NDK: `28.2.13676358` (Flutter 3.47.1's Android plugins require this newer
  NDK; it supersedes the originally proposed 27.3 pin)
- ABIs: `arm64-v8a`, `x86_64`

`tools/build_android_sdcc_stages.ps1` reproducibly builds namespace-isolated
stage objects from the pinned fork. Production CMake links those objects into
`libpieblock_sdcc_native.so`; probe executables and intermediate objects are
never packaged. The embedded host accepts only `sdcpp`, `sdas251`, and `sdld`
dispatches generated by the SDCC driver and rejects shell metacharacters and
unknown tools.
