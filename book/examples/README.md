# 教材第 5 章示例工程

本目录是《PIE-Block 教材》第 5 章「工程机器人与高级构型」配套的示例工程，
可直接导入 PIE-Block（格式版本 17，工程项目）。三个 `.pieproj` 与正文的动作表
一一对应：正文讲控制律，这里给出可打开、可校验、可生成固件的完整工程。

| 文件 | 构型 | 动作行 | 说明 |
| --- | --- | --- | --- |
| `mecanum4.pieproj` | 四轮麦轮 | 6 行 | P74–P77 四路平滑电机，整数麦轮解算，支持前后/左右平移 |
| `omni3.pieproj` | 三轮全向 | 5 行 | P74–P76 三路平滑电机，按 120° 布置做全向解算 |
| `arm2dof.pieproj` | 二自由度机械臂 | 10 行 | MP03/MP74 两路主舵机，按几何关系逆解关节角并换算舵机角度 |

## 导入方式

1. 打开 PIE-Block，在开始页选择「打开项目」；
2. 选中本目录下的 `.pieproj` 文件（三者都是工程项目，打开后向导按工程流程走）；
3. 进入「代码」页即可看到生成的 C 源码，进入「编译/烧录」页可构建固件。

工程里已经关闭预制底盘（`chassis.enabled = false`），四轮/三路电机全部由
动作行的表达式驱动。如果打开后出现红色校验提示，说明仓库里的示例被改坏了——
请先运行本文末尾的校验命令定位问题，不要直接拿它烧录。

不装 PIE-Block 也可以离线检查示例：

```bash
# 校验并生成 C 到 build/book_examples/（会打印每条 RunMode1 摘录）
dart run tool/generate_book_examples.dart

# 单元测试：解析、校验、代码生成与试算结果
flutter test test/book_examples_test.dart
```

## 硬件假设

- **扩展板**：8 个扩展脚全部显式指定了角色。P60/P62/P64/P66 属于 PWMA 组，
  P74/P75/P76/P77 属于 PWMB 组；麦轮与全向示例按「PWMA 50Hz、PWMB 10000Hz」
  初始化，机械臂两个 PWM 组都用 50Hz。
- **遥控器**：2.4G 接收机，通道 36（工程模板默认值），摇杆死区 100；
  摇杆轴量程约 ±2047。示例里的 `LX`/`LY`/`RX`/`RY` 指左/右摇杆的水平/垂直轴。
- **麦轮示例**：四个平滑电机接 P74–P77；P60–P66 未使用。
- **全向示例**：三个平滑电机接 P74–P76，P77 及 P60–P66 未使用。
- **机械臂示例**：两个主舵机接 MP03/MP74（PWM 50Hz，中位偏移 0）；
  8 个扩展脚全部标记为「未使用」。
- 示例只演示控制律，不含裁判系统、功率限制、超电管理等比赛逻辑；也没有写
  「保留底盘」模式（模式数为 1）。

## 安全提示

- **先架空再上电**：第一次编译烧录前把车架空、机械臂悬空，确认四个/三个电机
  转向正确、舵机不撞机械限位，再落地运行。
- **断电插拔**：扩展板、电机、舵机接线全部在断电状态下完成，避免带电插拔
  烧毁驱动。
- **舵机行程**：生成的固件会把主舵机角度钳位在 ±90°（`pb_servo_duty` 内部
  还会再限 250–1250 占空比）；但机械结构上的限位仍需自己确认，不要用软件
  钳位去硬顶机械限位。
- **参数先小后大**：表达式输出统一按 10000（电机）/ ±90°（舵机）量程设计；
  上电初期建议把车架起、用手柄小幅度打杆观察，确认方向与幅值后再加大。
- **改动后重校验**：修改动作行后运行上面的校验命令或单元测试；动作表与
  教材不一致时测试会直接失败。
- 示例工程不承诺适配具体车体：引脚分配、电机方向、舵机中位都要按实车重新
  核对后再烧录。

## 三个示例的控制律

### 四轮麦轮（`mecanum4.pieproj`）

```text
vx = -LY                 vy = -LX
P74(左前) = (vx - vy) * 10000 / 2047
P75(左后) = (vx + vy) * 10000 / 2047
P76(右前) = (vx + vy) * 10000 / 2047
P77(右后) = (vx - vy) * 10000 / 2047
```

变量声明为整数，所以这段解算是纯整数运算（除不尽时向零截断），与
STM32/C251 上直接写 `int` 的行为一致。

### 三轮全向（`omni3.pieproj`）

```text
vx = -LY                 vy = -LX
P74 = vx * 10000 / 2047
P75 = (-0.5 * vx + 0.866 * vy) * 10000 / 2047
P76 = (-0.5 * vx - 0.866 * vy) * 10000 / 2047
```

三路输出按 120° 分解，0.866 是 `sin 60°` 的两位小数近似。

### 二自由度机械臂（`arm2dof.pieproj`）

```text
x   = max(RX * 0.05, 20.0)
y   = max(-RY * 0.05, 0.0)
r2  = x*x + y*y
c2  = (r2 - 24400.0) / 24000.0
c2c = min(max(c2, -1.0), 1.0)
s2  = sqrt(1.0 - c2c*c2c)
q1  = atan2(y, x) - atan2(100.0*s2, 120.0 + 100.0*c2c)
q2  = atan2(s2, c2c)
MP03 = q1 * 180.0 / PI
MP74 = q2 * 180.0 / PI - 90.0
```

其中 24400 = 120² + 100²、24000 = 2 × 120 × 100，对应大臂 120、小臂 100 的
几何参数；`x`/`y` 的下限把目标限制在前上方，避开原点附近和向后工作时肩关节
解落到 ±90° 之外。主舵机目标角度在生成代码里会被钳位到 ±90°，不会因为
逆解越界而顶坏结构。

## 内置 SDCC 编译验证

应用构建产物里带有 SDCC MCS251 工具链和 STC32G 固件头文件，可对生成的 C
做只编译不链接的语法/类型检查（在仓库根目录执行）：

```bash
ROOT=build/linux/x64/debug/bundle/data/pieblock_runtime
FW=$ROOT/stc32g_sdcc
$ROOT/sdcc-toolchain/bin/sdcc -mmcs251 --model-large --stack-auto \
  --opt-code-size --constseg CSEG -c build/book_examples/mecanum4.c \
  -I$ROOT/sdcc-toolchain/include -I$ROOT/sdcc-toolchain/include/mcs51 \
  -I$FW/include -I$FW/startup -I$FW/libraries/drivers/inc \
  -I$FW/libraries/boards/inc -I$FW/projects/ROBOMASTER_ENGINEER/inc \
  -o build/book_examples/mecanum4.rel
```

`omni3.c`、`arm2dof.c` 同理替换文件名即可。编译退出码为 0 即通过；SDCC 打印的
`warning 110`、`__has_builtin` 重定义等属于内置编译器噪声，应用内的构建日志
本来就会过滤掉。
