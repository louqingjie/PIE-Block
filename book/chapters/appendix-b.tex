\chapter{常见问题（FAQ）}
\label{app:faq}

\textbf{车完全没反应，从哪里查？}\quad
按顺序：手柄与主控板是否都已上电；手柄通道号（长按 mode 键读出）与
配置里的通道号是否一致；死区是否填得过大；烧录页是否显示固件已成功
写入。通道不一致是最常见原因。

\textbf{推前进却后退（或左右反了）？}\quad
手柄摇杆的极性因批次可能相反。架空低速核对：推上应四轮同向前进，推左
应原地左转。个别轮子反了改“单轮方向”；整机转向反了打开“反转左右
转向”；前后整体反了按实车实测处理，必要时用“试算表达式”核对摇杆
符号（第~\ref{ch:gencheck}~章）。

\textbf{拨弹电机“一卡一卡”？}\quad
步兵的拨弹电机只能落在固定 50\,Hz 的 PWMA 组，占空比台阶大，低速发弹
不平滑是既定取舍。可以适当提高拨弹速度、缩短单发时长，或改用“目视
闭环连续拨弹”模式。

\textbf{摩擦轮带不动、转速上不去？}\quad
检查目标占空比是否低于 650（校验器会提醒）；确认机械阻力正常；电调
首次使用需完成油门行程学习。摩擦轮上限填不到 800 以上——500--800 是
有意的设计范围，1100 是不可逾越的红线。

\textbf{未检测到 ISP 主控板？}\quad
关闭四个供电开关（主控板 SERVO、POWER；拓展板 POWER、BOOSTER），把
主控板断电后重新上电进 ISP；Linux 下先安装 udev 规则并重新插拔。
烧录成功后 HID 设备消失是正常现象。

\textbf{写块无响应、烧录中断？}\quad
换 USB 口与数据线，避免经过集线器；确认没有其他程序占用设备。应用会
自动重发若干次并保留失败原因在日志里。

\textbf{首次编译报“部署 SDCC 工具链失败”？}\quad
常见于中文用户名路径或杀毒软件占用运行时目录。把项目与应用的缓存目录
移到纯英文路径，或把工具链目录加入杀毒软件白名单后重试。

\textbf{Keil 构建报错但日志是 0 Error(s)？}\quad
Keil 的命令行退出码不可靠，以日志中的 \texttt{0 Error(s)} 为唯一判据。
报找不到 \texttt{C251.EXE} 时检查 Keil 目录选择与 \texttt{TOOLS.INI}
的 \texttt{[C251]} 段；许可证异常时在烧录页重新应用许可证（密钥只写入
Keil 的 \texttt{TOOLS.INI}）。

\textbf{旧版本创建的 .pieproj 打不开？}\quad
格式 17 与 15、16 完全不兼容，应用拒绝打开是刻意设计。用对应的旧版
PIE-Block 打开另存，或按第~\ref{ch:projects}~章的字段说明手工迁移。

\textbf{表达式报“未定义变量”？}\quad
变量行排在引用行之后，或变量名大小写不一致。变量必须在同一模式内先定义
后使用；跨模式共享时同名变量会自动提升为全局变量，但类型必须一致。

\textbf{表达式检查报了编译错误，但表达式看起来没问题？}\quad
表达式编译检查编译的是完整固件：错误可能来自表达式与固件其余部分的
交互（类型、内存模型）。按错误信息里的 \texttt{/*@expr:...*/} 定位
注释回到对应行修改。

\textbf{动作行能不能拖动排序？}\quad
可以。拖动动作行左侧的手柄调整顺序；列表顺序就是执行顺序，变量行仍须排在
引用它的行之前。

\textbf{模式切换后轮子停了？}\quad
新模式没有映射这四路输出。工程项目的每个模式都要把需要的输出写全；
模式切换时未映射的电机与抖动电机会被清零（\texttt{PrepareMode}），舵机
保持最后位置。

\textbf{Web 版为什么不能烧录？}\quad
浏览器访问不了 USB-HID 设备，也没有本地 SDCC 工具链。配置、检查与
生成代码在 Web 版完全可用；编译烧录回桌面端完成，或用 Android 的
OTG 直连。
